# meadow — Python Source Code

## Purpose

Owns the Python package `meadow`: the shared business-rules engine (`meadow.rules`), and later the worker and frontend services. Python is the home of flexible business logic and the UI (see root AGENTS.md).

## Ownership

- Owns all files under `meadow/`.
- `meadow/rules/` — RestrictedPython sandbox and the script contract `run(obj, ctx, result)`.
- `meadow/tabular.py` — shared CSV/XLSX ↔ MEF adapter (pure parsing/mapping helpers).
- `meadow/mef.py` — pure MEF JSON helpers (detect/parse/summarize, preview rows) for the import page.
- `meadow/frontend/display.py` — pure display helpers shared by all pages (`resolve_value`, `status_badge`, `completeness_badge`; no NiceGUI state). Pages import them from here (not from `grid.py`).
- `meadow/frontend/object_picker.py` — the shared picker dialog used wherever an object is selected; exports `open_object_picker` (object-specific: Search + Structure tabs, optional multi-select), `open_structure_picker` (the generic dialog underneath — pluggable `load_children`/`on_pick`, tabs only when a `search` callback is given, so tree-only dialogs are possible) and `render_picker_hit`, `OBJECT_ROOT_ID`.
- **Sequenzielles Editieren** (`meadow/frontend/edit_queue.py` + grid/form): the `edit_note` button in the grid toolbar queues the **selected rows** in their grid order and opens the first one (`start_sequential` → `edit_queue.start_queue(ids, current_url())`, notify `seq.no_selection` when the selection is empty). The queue (`{ids, origin}`) lives per user in `app.storage.user["edit_queue"]` — **no server state, no new endpoint** — so it survives the navigation between objects; the origin URL is the current grid view (filters preserved). The product form shows a **progress banner** (`seq.position` „Object i of n“ + `ui.linear_progress`) with **Save & next** (`save(next_object=True)`), **Skip** (`skip_object`) and a close icon (`stop_sequence`); a failed save keeps the object open, the last object ends the sequence (`seq.finished` → back to the origin URL), and the form's **Back** button (`go_back`) stops a running sequence as well. `next_object_id`/`position_of` are pure helpers and unit-tested.
- `meadow/worker/` — async NATS request/reply worker serving `rules.evaluate` (`python -m meadow.worker`).
- `meadow/frontend/` — the NiceGUI web application (`python -m meadow.frontend`).
- `meadow/frontend/static/` — static client assets (logos, images, icons); owned by `meadow/frontend/static/AGENTS.md`.

## Local Contracts

- Implementation stays consistent with `plan/detail/business-rules.md` and the root AGENTS.md (package manager `uv`, `.venv/`, `pyproject.toml`).
- The rules engine is a shared library; its consumers are the Rust core (synchronous evaluation endpoint, Phase 4) and the Python worker/frontend.
- `meadow.rules` public API: `execute_rule`, `compile_rule`, `Context`, `Result`, `DEFAULT_WHITELIST`, and the `RuleError` hierarchy (`RuleCompileError`, `RuleTimeoutError`, `RuleMemoryError`).
- Rule scripts use `def run(obj, ctx, result)`; injected globals are `obj` (read-only view), `ctx`, `result`, `log`, plus whitelisted modules (default: `json`, `datetime`, `math`, `re`, `statistics`, `decimal`, `typing`, `uuid`, `collections`).
- `meadow.worker` (`protocol.py`, `rules_service.py`, `log_sender.py`): NATS request/reply service on subjects `rules.evaluate` and `rules.compile` (defaults) that evaluates `EvaluationRequest` payloads and validates scripts via `EvaluationCompileRequest`; rule exceptions are fail-closed (recorded in `failed`). Curated worker logs (rule failures, lifecycle) are buffered (`LogSender`, bounded, drop-oldest) and flushed to `POST /system/logs`; logging config (`log_persist_level`/`log_persist_categories`) is refreshed from `GET /system/settings`. Entry point `python -m meadow.worker`; env `NATS_URL` (default `nats://localhost:4222`), `RULES_EVALUATE_SUBJECT`, `RULES_COMPILE_SUBJECT`, `PIM_CORE_URL` (default `http://localhost:8080`), `LOG_INGEST_API_KEY`, `LOG_FLUSH_INTERVAL_S`, `LOG_CONFIG_REFRESH_INTERVAL_S`.
- `meadow.worker.http` (`http.py`): `loopback_host(url)` rewrites `localhost` → `127.0.0.1` to avoid the Windows IPv6-first resolution stall (~2 s per new connection; the core binds IPv4 only). Every worker HTTP entry point normalises `core_url` through it before issuing requests, and `meadow/frontend/api.py` does the same via `_loopback_host`. Do **not** build core URLs with `localhost`. (Webhook **target** URLs are external and must NOT be rewritten.)
- `meadow.worker.jobs` (`jobs.py`): JetStream job consumer on `jobs.*` (stream `JOBS`, durable pull consumer `job-worker`). `JobRunner` parses `JobMessage`, reports `job_run` status via `PATCH /jobs/runs/{run_id}` (`X-Api-Key` = `LOG_INGEST_API_KEY`), and dispatches to handlers registered by job type; unknown types are marked `failed` + terminated, handler failures are negative-acked for retry; on the final delivery attempt (`num_delivered >= max_deliver`) a failing job is published to the `JOBS_DLQ` stream (`jobs.dlq.<type>`) and terminated. Messages are processed with bounded concurrency (`JOBS_CONCURRENCY`, default 4; `process_messages` + `asyncio.Semaphore`). Env `JOBS_SUBJECT`, `JOBS_STREAM`, `JOBS_CONSUMER_DURABLE`, `JOBS_ACK_WAIT_S`, `JOBS_MAX_DELIVER`, `JOBS_CONCURRENCY`.
- `meadow.worker.business_rules` (`business_rules.py`): the `business_rule` job handler (recompute, Phase 5 step 4; Phase 7 *cascade*). For explicit `object_ids` it loads each object with **`?resolve_inheritance=true`** (plus an optional `parameters.locale`) so computed rules that read inherited values see them; for `applies_to` it loads via `GET /objects`. It evaluates the embedded rule script per object in the sandbox (bulk mode, ~30 s budget), persists declared-computed values via `PATCH /objects/{id}/computed`, and returns a per-object report stored in `job_run.result` (per-object failures are isolated). Sandbox evaluations are serialized by a module-level `asyncio.Lock` (`sys.settrace`/`tracemalloc` are not safe concurrently), while object I/O runs in parallel. A job with `trigger: cascade` is the inherited-computed recompute scheduled by the core after an ancestor save.
- `meadow.worker.imports` (`imports.py`): the `inbound_import` job handler (MEF import, Phase 6). It fetches the stored MEF document (`GET /imports/{document_id}`), applies active `normalization` rules (R3, loaded via `GET /rules`, evaluated in the sandbox with `mode="import"`, serialized on the shared `business_rules.evaluation_lock`), normalizes quantified `{"value":…,"unit":…}` values to the canonical SI unit via `GET /units/convert`, upserts objects by business key (`match_by_key`, via `GET /objects/by-key`), then — with `parameters.match_by_id` — by an existing core record id (`GET /objects/{id}`, for MEF documents whose `id` is a Meadow record id, i.e. a MEF roundtrip) — or by source reference (`GET /objects/by-source`, the MEF object `id` + document `source`; `source_id`/`source` stored via `POST /objects`), then `POST /objects`/`PATCH /objects/{id}`, creates references (mapping the MEF `type` name to the definition key `rel_<name>`), and returns a per-object/per-reference report stored in `job_run.result` (failures are isolated). With `emit_events: false` the writes pass `?emit_events=false` and the handler emits one `import.completed` summary event via `POST /imports/{document_id}/complete`. Writes use the `X-Api-Key` machine-to-machine path.
- `meadow.worker.exports` (`exports.py`): the `outbound_export` job handler. **Two paths.** (1) `json_export` connector (Phase 6): filters objects by `parameters.filter` (`type`/`status`; `status` filtered client-side), fetches them via `GET /objects`, re-emits quantified values (canonical-SI numbers) as `{"value":…,"unit":…}` in the attribute's display unit (attribute definitions via `GET /attribute-definitions`; conversion via `GET /units/convert`), builds a MEF document (`format_version`, `source`, `created_at`, `objects`), and stores it in `job_run.result` (`{connector, exported, document}`). (2) **Structured export (Phase 9, UI-guided):** when `parameters.source` is set (`collection|type|category|saved_search|selection`), it resolves the object set via `_resolve_objects` (collection → `GET /collections/{id}/members`; saved_search → `POST /saved-searches/{id}/execute`; selection → `object_ids`; then `GET /objects?ids=...`), loads multilingual/language-map metadata (`_load_multilingual`/`_load_languages`), builds columns/rows (`_build_columns`/`_build_rows`, expanding multilingual attributes into `<attr>_<locale>` columns with fallback via `_pick`), and stores `{format, exported, columns, csv|document|xlsx_base64}` in `job_run.result` (no binary blob; the file is serialised by `GET /exports/{run_id}/file`). CSV via `csv.writer` (`_serialize_csv`), XLSX via openpyxl (`_serialize_xlsx`). When `options.email_to` is set, `_maybe_email` sends the finished file as an attachment (best-effort; the outcome is recorded under `result.email`). `_finalize` runs **archival + e-mail** after the result is built: when S3 is configured (`meadow.worker.storage`) the file is uploaded and, above `EXPORT_INLINE_MAX_BYTES` (default 1 MB), the inline `csv`/`xlsx_base64`/`document` are dropped — `result.archive` then holds `{bucket, key, size, url, expires_in}` (a presigned download URL). Registered in `meadow/worker/__main__.py`.
- `meadow.worker.mail` (`mail.py`): minimal env-configured SMTP sender for the worker. `SmtpConfig.from_env()` reads `SMTP_HOST` (unset = disabled), `SMTP_PORT` (default 1025), `SMTP_FROM` (default `meadow@localhost`), optional `SMTP_USERNAME`/`SMTP_PASSWORD` and `SMTP_STARTTLS`; `send_with_attachment(...)` sends one plain-text e-mail with a single attachment via `aiosmtplib`. For local development the `mailhog` service in `docker-compose.dev.yml` catches all mail (SMTP 1025, web UI/API 8025).
- `meadow.worker.storage` (`storage.py`): S3/MinIO archival for export results (path-style SigV4 via `boto3`). `S3Config.from_env()` reads `S3_ENDPOINT_URL`/`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`/`S3_BUCKET`/`S3_REGION`/`S3_PRESIGN_EXPIRY` (unset endpoint/bucket = disabled); `archive_export(config, key, content, content_type, download_name)` creates the bucket on demand, uploads the bytes and returns `{bucket, key, size, url, expires_in}` with a presigned GET URL. Dev uses the `minio` service in `docker-compose.dev.yml` (API 9000, console 9001).
- `meadow.worker.connectors` (`connectors.py`): loads enabled connectors from the core (`GET /connectors?type=…&enabled=true` with `X-Api-Key`) into typed config models. `fetch_webhook_configs` raises on transport failure; `load_webhook_configs` combines it with the `env_bootstrap_config()` fallback (`WEBHOOK_URL`, …) so the `connector` table is the durable source of truth and environment variables only seed the initial value.
- `meadow.worker.webhooks` (`webhooks.py`): the webhook outbound connector (Phase 6). One NATS pull consumer on `events.crud` (stream `EVENTS`, durable `event-webhook`) fans each event out to every configured endpoint (`WebhookFilter`: `event_types`/`object_types`/`attribute_changes`; `WebhookConfig`: `key`, `url`, `method`, `headers`, `timeout_s`, per-connector `coalesce`) with at-least-once semantics: a message is acknowledged only after every matching connector path has settled (`_DeliveryTracker`); delivery failures are negative-acked for NATS redelivery and dead-lettered to `EVENTS_DLQ` (`events.dlq.webhook`, payload carries the `connector` key) on the final attempt. When `coalesce.enabled` is set, events are buffered per connector/`object_id`+`event_type` and a flush loop delivers only the last event per window (with `coalesced`/`bundled_count` flags), acknowledging the buffered messages on flush. `serve_webhooks_dynamic` supervises the consumer and **live-reloads** connector config every `WEBHOOK_RELOAD_INTERVAL_S` (default 30) — on change the consumer task is restarted with the new config (shared durable consumer keeps at-least-once across restarts), so no worker restart is required; a load failure keeps the current config. Env fallback: `WEBHOOK_URL`, `WEBHOOK_METHOD`, `WEBHOOK_HEADERS`, `WEBHOOK_FILTER_EVENT_TYPES`/`_OBJECT_TYPES`/`_ATTRIBUTES`, `WEBHOOK_COALESCE_ENABLED`, `WEBHOOK_COALESCE_WINDOW_S`, `WEBHOOK_ACK_WAIT_S`, `WEBHOOK_MAX_DELIVER`, `WEBHOOK_NAK_DELAY_S`.
- `meadow.worker.collections` (`collections.py`): the `collection_refresh` job handler (Phase 9). It reads `message.parameters.collection_id` and calls `POST /collections/{id}/refresh` (X-Api-Key) on the core, returning `{collection_id, count}` stored in `job_run.result`. Registered in `meadow/worker/__main__.py`.
- `meadow.worker.config_import` (`config_import.py`): the `config_import` job handler (MCF, Phase 9). It reads `message.parameters` `{document_id, mode}` (`dry_run`|`merge`|`replace`), fetches the stored MCF document (`GET /imports/{document_id}`), re-applies it via `POST /config/import?mode=...` (X-Api-Key), and returns `{mode, report}` stored in `job_run.result`. Registered in `meadow/worker/__main__.py`.
- `meadow.worker.bulk` (`bulk.py`): the `bulk_operation` job handler (Bulk-Wizard, Phase 7). It reads `message.parameters` `{op, object_ids, parameters}`, applies the operation per object (`set_attribute`/`clear_attribute` via `PATCH /objects/{id}`, `change_status`, `send_for_approval`, `add_category`/`remove_category` via `POST`/`DELETE /references`, `change_parent`, `replace_text`, `delete`), isolates per-object failures, and returns `{op, processed, succeeded, skipped, failed, replacements, approvals, results[]}` stored in `job_run.result`. **`replace_text` (Find & Replace, Phase 9):** replaces a literal `search` (with `replace`, `attribute` — empty = all text attributes — and `case_sensitive`) in every string leaf of an attribute value (`replace_in_value` walks strings, multilingual maps, lists and dicts alike; a lambda-based `re.sub` keeps backslashes in the replacement literal, case-insensitive by default). `_is_replaceable` limits the all-attributes mode to non-computed `text` definitions plus the convention fields (no definition, e.g. `name`) — enum codes and numbers stay untouched; the definitions are fetched once per run and cached. Objects without a match are reported as `skipped` (not `succeeded`) and carry `changed: 0`; the run-level `replacements` counts occurrences. **Approval (Phase 9):** `send_for_approval` transitions every object into `parameters.approval_status` (default `DEFAULT_APPROVAL_STATUS` = `in_review`) via `set_status`; a rejected `workflow_guard` transition is a per-object **error** for this op. With `parameters.send_for_approval = true` on a data-changing op the worker calls `request_approval` **after** the change (`_NO_APPROVAL_OPS` = `change_status`/`send_for_approval`/`delete`; an op that reported `changed: 0` is skipped): a rejection leaves the change applied and is reported as `approval_error` instead of `approval`, and `approvals` counts the successful transitions.
- `meadow.tabular` (`tabular.py`): the pure CSV/XLSX → MEF adapter shared by the frontend import page (and any future worker-side adapter). `parse_csv` (delimiter sniffing `,;\t|`, decoding `utf-8-sig`/`utf-8`/`cp1252`/`latin-1`), `parse_xlsx`/`sheet_names` (openpyxl, read-only/data-only), `parse_table(name, content, …)` dispatches by extension (`.xlsx`/`.xlsm` → XLSX, else CSV), `build_mef(table, mapping, default_type=…, source=…)` builds a MEF document from `TableData(columns, rows)`. Mapping target syntax: `""` = ignore, `id`/`type`/`status` = base fields, `<attribute>` = plain value, `<attribute>|<locale>` (`LOCALE_SEPARATOR`) = multilingual `{locale: value}`. Empty `type`/`status` cells fall back to the default type / `draft`. The module is import-light (openpyxl is imported lazily inside the XLSX functions).
- `meadow.frontend.attribute_definitions` (`attribute_definitions.py`): the `/attribute-definitions` admin page (admin/superadmin only) listing attribute definitions in an AG-Grid and providing a create/edit dialog over `POST`/`PATCH /attribute-definitions` (fields `type`, `label` (en/de), `group_ids` (list, many-to-many), `inheritable`, `is_key`, `multilingual`, `applicable_types`/`required_types`, `unit_id`/`display_unit_id`, `enum_set_id`, `description`, `computed` fields). **Enum attributes reference a reusable enum set (Phase 9):** for `enum` attributes the dialog shows an **`Enum set` select** (`enum_set_select`, options from `client.list_enum_sets`, keyed by the full `enum_set:<key>` id) plus a **"Manage enum sets"** button (→ `/enum-sets`); on save it sends `enum_set_id` instead of `constraints.enum_values`. The option list/remap editor moved to the `/enum-sets` admin page. `views.py` registers it via `_IMPLEMENTED_ROUTES`. Double-click on a grid row opens the edit dialog (resolves the full definition by id from `definitions`). A **delete** action (`DELETE /attribute-definitions/{id}`, `?force=true` for in-use definitions) shows a confirmation dialog and surfaces the 409 conflict message when the attribute is in use. An inline **Attribute groups** section (`group_grid`) allows create/edit/delete of groups (`POST`/`PATCH`/`DELETE /attribute-groups`, fields `name`, `label`, `position`, `applicable_types`), and the group column in the grid renders all groups of an attribute (the dialog's group select is `multiple=True`). The group grid also offers an **Edit-group** button and a **column picker** (dialog) that toggles column visibility and persists the per-user visibility in `app.storage.user["attr_def_group_columns"]` (mirrors the product grid's saved views). Editing resolves the **full** group record by id (`_group_for`) — the rendered rows carry resolved display strings (label, comma-joined `applicable`), not the raw `label` dict / `applicable_types` list the editor needs. A **filter bar** (free-text name, group select, type select) above the definition grid narrows the rows client-side (`filters` + `_matches`). The `Attribute groups` expansion uses a green header (`header-class=bg-green-2 text-green-9`), matching the product-form section headers.
- `meadow.frontend.enum_sets` (`enum_sets.py`): the `/enum-sets` admin page (admin/superadmin only, nav „Enum Sets“) for **reusable enum sets (Reference Data)**. It lists sets (`client.list_enum_sets`) in an AG-Grid (Name, Label, Options count, Position, Updated) with a name filter, and a create/edit dialog over `POST`/`PATCH /enum-sets`: `name` (read-only on edit), `label` en/de, `position`, and a **"Manage options"** action. The options editor dialog (`render_options`, refreshable) manages the set's options per row (`code` + EN/DE labels + `active` + remove); **Add option** appends a row, saving reconciles via `POST`/`PATCH /enum-options` and `PATCH /enum-sets/{id}` with `options` + `option_remap` (a removed used option opens a **re-map dialog**). `DELETE /enum-sets/{id}` is blocked (409) while an attribute references it. `api.CoreClient` gained `list_enum_sets`/`create_enum_set`/`update_enum_set`/`delete_enum_set`/`list_enum_options`/`create_enum_option`/`update_enum_option`/`delete_enum_option`.
- `meadow.frontend.enums` (`enums.py`): pure helpers to resolve a definition's enum set (`set_for_definition`), its `[{code,label}]` for a locale (`enum_options`), a `{code:label}` map (`enum_code_label_map`) and a single label (`enum_label_for`). Falls back to `constraints.enum_values` when a definition references no set. Used by the product form (`form.py`) and the object grid (`grid.py`).
- `meadow.frontend.multilang` (`multilang.py`): reusable **multilingual value editor** (`multilingual_value_editor`, `base_lang`, `active_data_languages`). Renders a current-UI-language input + language-icon button (dialog for all active data languages) and writes a `{lang: value}` map into `store[key]`; `in_row=False` renders inline for compact rows. Replaces the old hard-coded `Label (DE)`/`Label (EN)` input pairs in the admin dialogs (attribute definitions/groups, units, object types, relation types, enum sets incl. option labels).
- `meadow.frontend.units` (`units.py`): the `/units` admin page (admin/superadmin only) for **unit catalog management** (nav „Units“). It lists the catalog (`GET /units`) in an AG-Grid (Symbol, Label, Dimension, SI base, Factor, Offset, System) with a **filter bar** by dimension (client-side via `filters` + `_matches`) and a **System badge** column rendered via `html_columns` (default = neutral, custom = warning). A **"New unit"** button and row **double-click** open a create/edit dialog over `POST`/`PATCH /units`: fields `symbol`, `Base unit (SI)` select (from the catalog, sends the **bare** record key e.g. `unit_m`), `Label (DE/EN)` (hybrid editor: current-UI-language input + language icon for all data languages), `Factor`, `Offset`; on **edit** the symbol and base are read-only and a **Delete** button (`DELETE /units/{id}`, confirmation dialog) is shown for custom units. `api.CoreClient` gained `list_units`/`create_unit`/`update_unit`/`delete_unit`/`convert_units`. The `attribute_definitions` dialog's `unit_input`/`display_input` are **`ui.select`** dropdowns populated from the unit catalog (`unit_options`, keyed by bare key, resolved via `_unit_key`/`unit_key_by_symbol`/`_resolve_unit_key`).
- `meadow.frontend.object_types` (`object_types.py`): the `/object-types` admin page (admin/superadmin only, nav „Object Types“) for the **object-type registry** (flat, STIBO STEP / Akeneo family model). It lists types (AG-Grid: Name/Label/Key attributes/Label attribute/**Type**/Updated) with a name filter and a **Type badge** column rendered via `html_columns` (system = neutral, custom = warning), a create/edit dialog (`name` read-only on edit, `label` en/de, `description`, **`key_attributes` multi-select** + **`label_attribute` select** populated from `text` + non-multilingual attribute definitions), **Save/Reload**, and **Delete** (`client.delete_object_type`, confirmation, **409 when still used**; `system` types are locked client-side with a „System types cannot be deleted.“ notification and rejected server-side with 400). `api.CoreClient` gained `list_object_types`/`create_object_type`/`update_object_type`/`delete_object_type`. The `/attribute-definitions` page now populates its `applicable_types`/`required_types` dropdowns from the registry (`GET /object-types`) instead of deriving types from existing objects.
- `meadow.frontend.saved_searches` (`saved_searches.py`): the `/saved-searches` admin page (admin/superadmin only, nav „Searches & Collections“) with two tabs. **Saved Searches** (AG-Grid: Name/Refresh interval/Updated) with a name filter bar, create/edit dialog (`name`, `refresh_interval`, **query as JSON `ui.codemirror`** — the Query DSL), a **Run** action (`client.execute_saved_search` → `POST /saved-searches/{id}/execute`) showing `{count, ids}`, and **Delete** (`client.delete_saved_search`). **Collections** (AG-Grid: Name/Source search/Members/Refresh interval/Last refreshed) with a name filter, create/edit dialog (`name`, `saved_search` select, `refresh_interval` cron), **Refresh** (`client.refresh_collection`, confirmation), **Members** dialog (`client.list_collection_members`, table with Rank/Object/Type/Status), **Add members** dialog (`client.add_collection_members` → `POST /collections/{id}/members`, paste object IDs one-per-line/comma-separated, shows `added`/`skipped`), **Export** (navigates to `/export?collection=<id>` preselecting the collection source), and **Delete** (`client.delete_collection`). `api.CoreClient` gained `list_saved_searches`/`create_saved_search`/`update_saved_search`/`delete_saved_search`/`execute_saved_search`/`list_collections`/`create_collection`/`update_collection`/`delete_collection`/`refresh_collection`/`list_collection_members`/`add_collection_members`.
- `meadow.frontend.relation_definitions` (`relation_definitions.py`): the `/relation-definitions` admin page (admin/superadmin only, nav „Relation Types“) for the **relation-type registry** (composition `depends_on` + aggregations `category_member`/`collection_member`/`related`, plus custom aggregations). The columns are read-only (inline editing stays with the working language) and are enabled through the column picker or a personal view; `export_fields()` maps a visible language column back to its attribute name and deduplicates against the working-language column, because the export expands multilingual attributes per requested locale. Note (AG Grid): a column that starts hidden is **appended at the end** of the unpinned columns when it is enabled, so the visible order is always "base columns, then the enabled columns in click order" (this applies to the attribute columns too). **Inline editing (Spalten editieren):** the working-language column of an editable attribute is `editable` with the matching editor (`_editor_props`: plain input for `text`, `cellDataType: number` for `number`, `cellDataType: boolean` (checkbox) for `boolean`, `agSelectCellEditor` with the localized option labels for `enum`, `agDateStringCellEditor` for `date` — values are stored as ISO strings). `is_editable_definition` keeps **computed** values (they belong to a rule), **quantified** values (`unit_id`, unit-aware editing lives in the form), `reference`/media and every **per-language column** read-only — an `enum` without resolved set options is read-only too (an empty select would be useless). The cells carry **typed** values (`editable_cells` → `editable_cell_value`), so `row_data` still supplies the display value for any attribute without a working-language entry (a value maintained in another language stays visible; editing writes the working language). `cellValueChanged` records the changed cells per object (`staged_cells`, the counter counts cells), and `save()` patches **only** the staged fields that really differ from the values the row was loaded with (`loaded_rows_by_id`), converting each edited cell back with `storable_cell_value` (enum label → stored **code**, multilingual merge into the working-language key, number parsing, boolean) — untouched attributes are never sent, and the core merges the item's attributes. **Double-click:** an editable cell opens the editor, a read-only cell opens the product form (`handle_open_cell` skips `editable_fields`, i.e. `_name` and every editable attribute). **Column sizing & headers:** two buttons in the filter bar size the columns — `fit_screen` → `sizeColumnsToFit` (fill the available width) and `straighten` → `content_widths()` (each column as wide as its longest header/cell text, markup stripped, capped at `MAX_CONTENT_CHARS` = 30 characters) applied via AG Grid's `setColumnWidths`; every column carries `headerTooltip = headerName` and the grid sets `enableBrowserTooltips: True`, so the full header shows as a native tooltip (AG Grid's own tooltip component does not appear in this bundle). **The visible column set is persisted per user** (`app.storage.user[COLUMNS_STORAGE_KEY] = "grid_columns"`, validated by `restore_columns` against the columns that still exist and re-applied with `apply_visibility` right after the grid is built), so it survives a reload, the browser-back from the product form and a re-login; the personal views (`views`) work the same and are stored in the same user storage (see the session/preference note above). The grid offers three left-panel views via icon buttons (`account_tree` = structure, `category` = categories, `collections_bookmark` = **Collections**): the **Collections** view is flat — it loads `client.list_collections` and renders each collection as a tree node (label + `collection` type + member count); selecting one calls `client.list_objects(token, collection=<id>)` and filters the grid via `GET /objects?collection=<id>` (`collection_member` aggregation). The action button in the filter row is view-dependent: **`unfold_less` (collapse-all)** only in the structure/category views, replaced by a **`refresh` (reload)** button in the Collections view (`reload_collection` → `POST /collections/{id}/refresh` to re-materialize members, then `client.list_collections` to refresh the member counts and `client.list_objects(collection=...)` to re-fetch the grid). While a collection is selected the tree/selection is **left untouched** on reload — re-sending the node list (e.g. via `set_nodes`/`update`) corrupts the LazyTree selection so the node toggles off on the next click; the tree is only re-rendered (to update counts) when no collection is selected. Leaving the Collections view resets the active collection, clears the `?collection=` URL param, and returns to the structure view. The **bulk-wizard target pickers** (category for `add_category`/`remove_category`, parent for `change_parent`) use the **shared picker** (`open_object_picker`, `target_types=["category"]` for categories) with a chosen-target label (`grid.bulk_nothing_picked`) — no more selects loaded with up to 1000 objects (`load_category_options`/`load_parent_options` are gone); the picked id lands in `parameters["category"]`/`parameters["parent"]` via `bulk_picked`. The bulk progress dialog polls the `job_run` every 2 s and, after `PENDING_WARN_POLLS` (10 → ~20 s) without the status leaving `pending`, shows `grid.bulk_pending_hint` — a queued job is only processed while the worker runs (`python -m meadow.worker`). The **column picker** is a **`ui.dialog`** (not a `ui.menu`): Quasar's `QMenu` auto-open does not fire in Firefox/Zen (both the sibling and the nested button/menu forms fail there), whereas a `ui.dialog` opens reliably in all browsers — the same pattern as the working "views" dialog. The toolbar is right-aligned (`Save` stays a text button, while `Discard`/`Views`/`Columns` are icon-only with tooltips) with the structure-panel toggle (`view_sidebar`) and the staged-change counter on the far left. The structure panel renders a **`LazyTree`** (`meadow/frontend/lazy_tree.py`, a `ui.tree` subclass) that **lazy-loads** children on expand: nodes with `hasChildren` are marked `lazy: true` (no `children` key) and Quasar `@lazy-load` is wired through a client-side `js_handler` (captures the `done(children)` callback in `window.__meadowLazy`, emits the node key) so the server fetches children (`CoreClient.list_object_children`, paginated) and feeds them back via `run_javascript`; the tree is height-constrained to its card (`min-height: 0`) and scrolls internally (`overflow-y: auto`) so the panel does not overflow (`virtual-scroll` is set but does not take effect in this NiceGUI/Quasar version). `LazyTree.update()` is a **no-op**: NiceGUI re-sends the whole `nodes` prop on *any* prop change (e.g. `selected`), which would discard the client-side lazy children and collapse the tree; node changes (the tree's search filter) are applied explicitly through `LazyTree.set_nodes()` (which re-sends the (filtered) node list via `super().update()`). Top-level nodes load from the Universal-Root via `list_object_children`, and **selecting a node filters the grid server-side** through `CoreClient.list_objects(ancestor=...)` (the client no longer holds the full tree). The grid also shows a **completeness column** (`_completeness`, coloured `completeness_badge`: grey 0 %, orange 1–99 %, green 100 %), fed by the core's `completeness` value for the working locale (`list_objects(..., locale=...)`, which passes `?locale=`; the filter bar's „Nur unvollständige“ switch uses `list_objects(..., missing_required=True)` → `?missing_required=true`, filtered in the core); the `_status` and `_completeness` columns are registered as `html_columns` so their badge HTML renders instead of being escaped. The left panel has a **two-line header** — line 1 a **`ui.button_group`** of two icon buttons (`account_tree` = Structure, `category` = Categories; active `color=primary`, tooltips) that switch the tree view, line 2 the filter field + collapse buttons. `set_view(view)` styles the active button, toggles the tree-selector visibility, and calls `render_tree(view)`, which clears a `host` column and rebuilds a `LazyTree` for the structure (all types, `?ancestor=` filter) or for the categories (`type == "category"` children only, loaded with `count_members=True` and shown with a `memberCount` counter in the node label; selection filters the grid via `list_objects(..., category=...)` → `?category=` aggregation). A **`ui.select`** (`grid.all_trees` "All trees" + each category root) lets the user pick which independent category tree to display (`selected_tree`); `render_tree` shows all roots for "all" or a single root node otherwise; a **`uncategorized_node`** is prepended to the category tree („Nicht kategorisiert“, `id __uncategorized__`) and selecting it filters the grid via `list_objects(..., uncategorized=True)` → `?uncategorized=true`. `current_tree` holds the active tree so the **collapse-all** action and the filter operate on it. A session-expiry detection (`api.is_session_expired`) redirects to `/login` when the core reports `invalid or expired token`. The grid also offers a **column picker** (`api.CoreClient.list_attribute_definitions` → `attribute_columns`, hidden by default) that toggles attribute column visibility via AG Grid `setColumnsVisible`, with the ID column pinned left, and **personal views** (a `ui.dialog` stores the current visible column set per user in `app.storage.user`, lists saved views and restores them per click, including delete). A **structure tree** (composition tree, `api.CoreClient.get_object_tree` → `enrich_tree_nodes` + `collect_subtree`) is rendered in a **resizable left panel** (`ui.splitter` (`w-full`, start 25 %, limits `(0, 60)`; width drag handle, spans the full available main width and height via `h-[calc(100vh-210px)]`, so the grid fills the viewport) inside a **padding-free card** (`p-0`, so the tree aligns with the page heading) with a filter field (`filter_tree_nodes`), a **collapse-all** button (`unfold_less` → `collapse_all()` via `tree.collapse()`; no "expand all" — a lazy tree expands per node on demand, since Quasar's `expandAll()` would otherwise load every descendant), kept on one line with the filter via `flex-wrap: nowrap` + `shrink-0`) and node labels showing name + type (`tree` header slot). The **Universal-Root container node is hidden** (its children are lifted to the top level via `tree_nodes = root_children`) and there is no separate "Structure" heading. The panel can be collapsed/expanded via `view_sidebar` in the toolbar (`toggle_panel` sets `splitter.value` to 0/25, grid takes the full width); selecting a node filters the grid to the subtree via `setGridOption('rowData', ...)`. The grid also has a **reference column** (`_refs`, 🔗) and a **reference-picker modal** (`ref_dialog`): clicking a row's 🔗 cell routes `grid.on('cellClicked', handle_ref_cell_clicked, ['data','colId'])` to `open_references(object_id)`; the modal lists the object's references **grouped & sorted by relation type** (composition `rel_depends_on` first, then aggregations by label; resolving the type label via `list_relation_definitions`), each chip carrying a remove button calling `delete_reference` (hidden for the composition `rel_depends_on`), an **empty-state message** (`grid.ref_empty`) when there are no references, a **relation-type dropdown** (`relation_options` from `list_relation_definitions` filtered to `kind == 'aggregation'`, keyed by the definition's **short record key** e.g. `rel_category_member` because `create_reference` expects that), and a **search field** (`search_references` → `picker_search`, hits rendered through the shared `render_picker_hit` with the target completeness badge) plus a **tree button** that opens the shared `open_object_picker` dialog (Search/Structure tabs, excluding the current object); hits/picks are added via `add_reference` (`create_reference`). A **product form** (`meadow/frontend/form.py`, route `/products/{object_id}`, reachable via the grid's row double-click `grid.on('cellDoubleClicked', handle_open_cell, ['data','colId'])`) loads the object (`get_object` with `resolve_inheritance`) plus attribute definitions, attribute groups and the **data languages** (`CoreClient.list_languages` -> `GET /languages`) and renders three **collapsible sections** (`ui.expansion` with a coloured `header-class`): **Stammdaten** (read-only object ID + `name` + business-key/required attributes), **attributes without group** and **attribute groups** sorted by `position`. Each section is an **aligned attribute table** (a column header row + rows of `label | value | language-icon`, using `flex-1` **filled** inputs), with **required-field asterisks** (`_is_required` from `required_types`) and an **inherited-value marker** (dimmed `swap_horiz` icon, tooltip) overridden on edit. The **current UI language is the main edit language** (`edit_lang = _base_lang(locale)`, no separate selector); multilingual attributes show an inline value plus a per-attribute **language icon** opening a **wider `ui.dialog`** (`w-[34rem] max-w-[90vw]`) that edits all data languages (`list_languages`) and reads/writes the session's **working copy** (`edited`), so applied values persist on reopen and feed the inline widget. A **jump menu** (`ui.select` "Jump to") expands and scrolls to a section (`scrollIntoView`). **Enum fields** show a **`+` button** that navigates to the `/enum-sets` admin page (options are managed centrally); the enum **select** is populated from the attribute's referenced enum set with **localized labels** (`meadow.frontend.enums`) and the **stored code** is saved. **Reference fields** (`build_reference_widget`) use a **searchable picker**: typing queries `CoreClient.picker_search` (`GET /objects/picker`), hits are filtered by the definition's `constraints.target_types`, and picking a hit **sets the attribute value to the target object ID**, rendered as a removable chip (label + type). Next to the search field a **tree button** opens the shared picker dialog (`open_object_picker`, Search/Structure tabs, `exclude_ids=[object_id]`) — picking there fills the chip the same way. Both pickers render their hits through the shared `render_picker_hit` (`meadow.frontend.object_picker`), which adds the target's **completeness badge** (`completeness` from `GET /objects/picker?locale=`, tooltip `form.target_completeness`) next to the pick button. A **Relations** section (`build_relations_section`) renders the object's **graph-edge relations** (`CoreClient.list_object_references`), **grouped by relation type** (`CoreClient.list_relation_definitions`; composition `depends_on` first, then aggregations by label) as **full-width coloured cards with a darker header** (orange = composition, blue = aggregation; header `bg-orange-2`/`bg-blue-2`, body `bg-orange-1`/`bg-blue-1`) carrying **Composition/Aggregation badges**, per-type counts, an **add picker** (`open_relation_picker`, a thin delegate to `meadow.frontend.object_picker.open_object_picker` → `CoreClient.picker_search` / `POST /references`, `target_types` from the definition, `exclude_ids=[object_id]`) with **two tabs**: *Search* (server-side full-text hits) and *Structure* (a `LazyTree` over the composition structure, loaded lazily via `GET /objects/{id}/children` from `OBJECT_ROOT_ID`; nodes whose type is not an allowed target type — or the object itself — are **greyed out** and non-selectable but stay expandable to reach allowed descendants, `node_hits` maps node id → hit), **remove** per aggregation (`DELETE /references/{id}`), a **re-parent** action for `depends_on` (`PATCH /objects/{id}/parent` via `CoreClient.reparent_object`), and **open target** navigation. The UI is a thin view over the graph — all reads/writes go through these core endpoints (no client-side joins/materialization). Selects/inputs use the **`filled`** style (background, no underline). An **"Only missing required fields" switch** (`form_show_missing` in `app.storage.user`) filters the section rows to the missing required attributes (`missing_required`) via a `ui.refreshable`, and an **attribute search bar** (`form.search_attributes`, Quasar `debounce` 300 ms) filters the rows by **localized label or attribute name**, hides sections without hits, **opens the matching sections**, and shows `form.search_hits`/`form.search_no_hits` (categories, relations and pinned fields stay visible; combines with the missing-only switch as an intersection). Every attribute row carries a **pin toggle** (`push_pin`); pinned attributes are rendered in a **sticky sidebar** ("Pinned attributes", `position: sticky` + own scroll) by `render_pinned`, using the same **editable** widgets (`build_value_widget`) on the same **working copy** (`edited`), so they save with the normal **Save**; the pin set is stored **per object type per user** in `app.storage.user["pinned_attributes"]` (survives reload, empty state hint, attributes no longer applicable to the type are skipped). Both refreshables clear their widget registries (`pin_buttons`, and the language dialog additionally refreshes the sidebar) so no stale widget handles are updated. A **completeness widget** and a **status selector** are shown; saving via `PATCH /objects/{id}` **surfaces the core's `error` message** (`CoreClient.update_object` raises `CoreError`) instead of a generic failure. The **grid export** (toolbar download button) opens a dialog with scope (**selected rows** / **all filter matches**) and format (CSV/XLSX/JSON); it posts a `selection` source to `POST /exports` (`client.create_export`), polls the job run (`_wait_export`) and downloads via `GET /exports/{run_id}/file` (`client.get_export_file`), reusing the currently visible grid columns as the field set (`_export_fields`, maps `_id`/`_type`/`_status`/`_name`/`attr_*` to `id`/`type`/`status`/`name`/`<attr>`). The products page uses `response_timeout=15`. Config env: `PIM_CORE_URL` (default `http://localhost:8080`), `PIM_FRONTEND_HOST`/`PIM_FRONTEND_PORT` (default `8081`), `UI_STORAGE_SECRET`.

- `meadow.frontend.api` (`api.py`): the async `CoreClient` wraps the headless core REST API. It **reuses a single long-lived `httpx.AsyncClient`** (`_api_client()` asynccontextmanager; `trust_env=False`) instead of building a new client per call, and `_loopback_host` rewrites `localhost` → `127.0.0.1`. This eliminates the Windows `localhost`-→-IPv6 first-reconnect stall (~2 s) that otherwise added ~2 s per pim-core call — the main cause of the "page starts loading" delay (each page made several sequential calls). Do **not** restore a per-call `httpx.AsyncClient()`. `config.CORE_URL` defaults to `http://127.0.0.1:8080` for the same reason.
- Frontend static assets are served from `meadow/frontend/static/` under `/static` (`app.add_static_files`); `/static` is exempt from the `AuthMiddleware` so unauthenticated pages (login) can load branding assets. See `meadow/frontend/static/AGENTS.md`.
