# meadow — Python Source Code

## Purpose

Owns the Python package `meadow`: the shared business-rules engine (`meadow.rules`), and later the worker and frontend services. Python is the home of flexible business logic and the UI (see root AGENTS.md).

## Ownership

- Owns all files under `meadow/`.
- `meadow/rules/` — RestrictedPython sandbox and the script contract `run(obj, ctx, result)`; the publish-guard example in the demo catalogue skips `ctx.actor == "system"`, so automated imports/bulk jobs may store published objects while a user publishing an incomplete product is blocked.
- `meadow/tabular.py` — shared CSV/XLSX ↔ MEF adapter (pure parsing/mapping helpers).
- `meadow/mef.py` — pure MEF JSON helpers (detect/parse/summarize, preview rows) for the import page.
- `meadow/frontend/display.py` — pure display helpers shared by all pages (`resolve_value`, `status_badge`, `completeness_badge`, `release_badges`, `channel_label`, `channel_options`, `dimension_options`, `taxonomy_type_names`, `taxonomy_options`, `own_attribute_names`, `text_attribute_options`, `declared_key_names` and the release vocabulary `RELEASE_STATUSES`/`DEFAULT_RELEASE_STATUS`; no NiceGUI state). `own_attribute_names(definitions)` lists the **own** attribute names (not the imported standard's `reference_data` vocabulary) for every picker that lets a user *choose* an attribute — relation edge attributes and the object type's key/label list; `text_attribute_options(definitions, declared)` builds the key/label options (own, single-language `text` plus the names the types already declare, so `name` — no definition at all — stays selectable) and `declared_key_names(object_types)` collects those declared names. `dimension_options(definitions, locale, primary_label=…)` builds the **category dimension** switcher (primary categorisation first, then every custom `category` relation type), `taxonomy_type_names(object_types)`/`taxonomy_options` the **taxonomy** switcher (node object types with `taxonomy: true`, fallback to the built-in `category`); both stay pure by taking translated labels from the caller. Pages import them from here (not from `grid.py`), which also keeps the admin page out of the other pages' import graph (import cycles: `grid` → `channels` → `multilang` → `grid`).
- `meadow.frontend.url_values` (`url_values.py`, Phase 9): the **UI** side of the `url` attribute type. It imports the pure helpers from `meadow.urls` (re-exported for the pages: `url_extension`, `media_kind`, `is_valid_url`, extension lists) and adds `open_url(url)` — images/videos in the preview dialog, everything else in a new tab — and `open_media_dialog(url)` (a `ui.dialog` with `ui.image`/`ui.video` plus "open in new tab"/"close", i18n `url.*`). `media_kind` stays the single source of truth for "is this an image/video?": the grid renderer receives the decision through the row marker `_media` (see `grid.py` below). Consumers: the **product form** renders a `url` attribute as a `ui.input` with `props("filled dense type=url")` plus an **open button** (`open_in_new`, tooltip `url.open`, disabled while the field holds no valid URL) that calls `open_url`; the **grid** edits the value inline as text; the **search form** treats `value_type: "url"` as a text field.
- `meadow.frontend.range_values` (`range_values.py`, Phase 9): **pure** helpers for the `range` attribute type (two numeric bounds `{"from": <number>, "to": <number>}`, canonical text form `from..to`): `is_range`, `range_bounds`, `range_value` (orders the bounds), `format_bound`/`format_range` (display `4 – 12.5`), `parse_range` and `NUMERIC_TYPES = ("number", "range")` for the "may carry a unit" decision. Consumers: the **product form** (two `ui.number` fields writing one value, labels `form.range_from`/`form.range_to`; it is *not* mirrored through `main_widgets` because a range is never multilingual), the **grid** (display only — `range` stays out of `EDITABLE_TYPES`) and `attribute_definitions.py` (keeps `unit_id`/`display_unit_id` for numeric targets). The core mirror is `attribute_definition_types.rs`.
- `meadow.frontend.export_fields` (`export_fields.py`, Phase 9): **pure** helpers for the export wizard's field selection (no NiceGUI): `attribute_names`, `group_members` (attribute group → members, plus the ungrouped ones; an attribute in several groups appears in each), `applicable`/`allowed_names` (the `applicable_types` filter — empty means every type, and without a chosen type everything stays visible) and `group_order` (by `position`, then display title) plus `selected_fields` (ticked fields in render order, base fields default to ticked). Consumer: `export_page.py`, which renders one `ui.expansion` per group. A catalogue with an imported classification standard carries thousands of attributes, so the flat list was unusable. **Both dedups must stay O(1) (set-based):** with the full ETIM standard (17 379 definitions) the earlier list-membership test cost 1.6 s (`attribute_names`) plus 1.7 s (`group_members`) on **every** page build of `/export` — measured 18.5 s → 12.0 s after switching to sets.
- `meadow.frontend.reference_data` (`reference_data.py`, 2026-09-13): **pure** rules for the `reference_data` flag of an attribute definition — the vocabulary an imported classification standard brings (380 feature definitions in the shipped ETIM 10.0 bundle, 17 377 in the full standard). `is_reference`, `has_value` (a language map counts when any entry is non-empty; `0`/`false` are values, `""`/`[]`/`{}` are not), `visible_in_form` (own attributes always, reference data only while the object already carries a value — nothing that exists may become unreachable), `visible_in_picker(..., include_reference=False)` for the surfaces that *choose* an attribute (export field selection, bulk target, find & replace) and `reference_names` for the count in a hint. Consumer rule: hidden where an attribute is **chosen**, visible where data is **read** (grid columns, class-features section, search). An attribute is adopted by clearing the flag in the attribute catalog. The **search form** follows the same rule: `SearchForm.show_reference` (switch `search_form.show_reference`, off by default, rendered in the conditions section when the catalog carries such fields) filters `field_choices`/`sortable_choices`; a field a condition already uses (`extra`) stays selectable, and the core keeps those fields filterable so a stored search still validates. A **`range` attribute** is offered as two numeric fields (its bounds, `attributes.<name>.from`/`.to`); `field_label` appends the translated bound (`search_form.bound_from`/`bound_to`) to the shared attribute label and strips the bound from the name fallback. **Pickers read the rule from here too:** wherever an attribute is *chosen* for a new purpose (`display.own_attribute_names` for relation edge attributes and the object type's key/label list) the standard's vocabulary stays out; the places that map or read **data** (import column mapping, connector field mapping, the class-feature picker) keep it, because a supplier file regularly fills the standard's fields and a class demands its features. Every one of those pages loads the **whole** vocabulary (`GET /attribute-definitions/vocabulary`) instead of the capped paged list — with `EF…` filling its first page, a freshly created own attribute was invisible there too (2026-09-17). Unit-tested in `tests/test_reference_data.py`, `tests/test_frontend_definitions.py`.
- `meadow.frontend.filters` (`filters.py`, 2026-09-13): the shared **table-filter dropdown** plus the pure `normalised` value rule. `filter_select(options, label="", on_change=…, value=None, multiple=False, classes="", tooltip="")` renders `filled dense clearable`, so every filter bar can go back to "no selection" (✕ = all) instead of forcing a choice once a value was picked — the two older spellings (a synthetic `{"": t("…all…")}` entry or nothing at all) are unified, and a `label` is optional (the grid's channel filter explains itself with a tooltip). `normalised` turns a cleared field into `""` (single) or `[]` (multiple), so a callback never sees `None` and never stores the string `"None"` (which would silently match no row). The change handler is **async**: an async callback (the grid's channel filter reloads the grid and calls `ui.run_javascript`) is awaited inside the NiceGUI event context — a detached task instead fails with "the current slot cannot be determined" (verified 2026-09-13). Unit-tested in `tests/test_filters.py`.
- Filter bars use `meadow.frontend.filters.filter_select` — do not add a plain `ui.select(...).props("filled dense")` above a table: a filter needs a way back to "all".- **Reference-data hiding (2026-09-13):** `form.py` filters its field list through `reference_data.visible_in_form`, so the vocabulary of an imported standard (380 ETIM features in the bundle) does not bury the own attributes — a reference attribute reappears as soon as the object carries a value for it, and the class-features section remains the read-only view of what the classification demands. `export_page.py` offers the vocabulary behind the `export.show_reference` switch (`reference_state`, hidden by default, label shows the count), `grid.py` hides it from the bulk-wizard target and the find/replace attribute selects, and the attribute catalog (`attribute_definitions.py`) shows a **Standard** column and hides the standard's vocabulary behind the `attr_def.show_reference` switch (off by default; the `hidden_hint` label names the count via `attr_def.reference_hidden`), while the `attr_def.field_reference` checkbox adopts a standard attribute into the own set. The older per-row filters `attr_def.filter_reference`/`attr_def.reference_own`/`attr_def.reference_standard` are gone — the switch is the one place that decides.- **Sequenzielles Editieren** (`meadow/frontend/edit_queue.py` + grid/form): the `edit_note` button in the grid toolbar queues the **selected rows** in their grid order and opens the first one (`start_sequential` → `edit_queue.start_queue(ids, current_url())`, notify `seq.no_selection` when the selection is empty). The queue (`{ids, origin}`) lives per user in `app.storage.user["edit_queue"]` — **no server state, no new endpoint** — so it survives the navigation between objects; the origin URL is the current grid view (filters preserved). The product form shows a **progress banner** (`seq.position` „Object i of n“ + `ui.linear_progress`) with **Save & next** (`save(next_object=True)`), **Skip** (`skip_object`) and a close icon (`stop_sequence`); a failed save keeps the object open, the last object ends the sequence (`seq.finished` → back to the origin URL), and the form's **Back** button (`go_back`) stops a running sequence as well. `next_object_id`/`position_of` are pure helpers and unit-tested.
- `meadow/worker/` — async NATS request/reply worker serving `rules.evaluate` (`python -m meadow.worker`).
- `meadow/frontend/bulk_edit.py` + `bulk_report.py` + `bulk_wizard.py` + `where_dialog.py` + `column_views.py` + `create_object.py` + `tree_panel.py` + `cell_values.py` + `view_switch.py` + `references_dialog.py` — the parts of the products page that were extracted out of `grid.py`'s `products_page` (`plan/detail/ai-code-quality.md` §4.11): the bulk wizard's decisions (`bulk_edit`: `build_parameters`, `missing_parameters`, `approval_supported`, `row_id`/`ids_from_rows`/`page_ids`), the reading of its report (`bulk_report`: `read_bulk_report`, `replace_target_options`), its UI (`bulk_wizard`: `BulkWizard`, `BulkConfigArea`, `WizardCatalogs`), the advanced-search dialog (`where_dialog`: `WhereDialog`, `has_conditions`, `saved_search_name`), the saved column views (`column_views`: `ColumnViews`, `read_views`), the create-object dialog (`create_object`: `CreateObjectDialog`, `normalized_name`/`missing_key_names`/`build_attributes`), the navigation tree (`tree_panel`: `TreePanel`, `TreeState`, `collection_label`/`collection_node`), the cell contract (`cell_values`: `as_number`/`as_bool`/`is_multilingual_map`, `storable_cell_value`, `build_patch`, `staged_patches` — an enum cell carries the label while the core stores the code, a multilingual edit merges into the working language, a reverted or vanished row is never sent), the panel's view rules (`view_switch`: `panel_visibility`, `ViewSwitch`) and the reference dialog (`references_dialog`: `ReferencesDialog`, `reference_groups`/`reference_chip`/`relation_options`). **Rule:** the page keeps the state and passes it in — decisions as pure functions, behaviour as `get_*`/`set_*`/`apply_*` callbacks, and the tree's page state as a frozen `TreeState` **snapshot** (read on every render, so nothing stale is drawn). ## Local Contracts

- Implementation stays consistent with `plan/detail/business-rules.md` and the root AGENTS.md (package manager `uv`, `.venv/`, `pyproject.toml`).
- The rules engine is a shared library; its consumers are the Rust core (synchronous evaluation endpoint, Phase 4) and the Python worker/frontend.
- `meadow.rules` public API: `execute_rule`, `compile_rule`, `Context`, `Result`, `DEFAULT_WHITELIST`, and the `RuleError` hierarchy (`RuleCompileError`, `RuleTimeoutError`, `RuleMemoryError`).
- Rule scripts use `def run(obj, ctx, result)`; injected globals are `obj` (read-only view), `ctx`, `result`, `log`, plus whitelisted modules (default: `json`, `datetime`, `math`, `re`, `statistics`, `decimal`, `typing`, `uuid`, `collections`). `Context` carries `rule_type`, `object_type`, `language`, `mode`, `actor` and — for **channel-specific releases** — `channel` plus `release_status` (the release target state; `withdrawn` marks a withdrawal), and for object writes **`missing_features`** (tuple of the unset mandatory **class features** of the object's taxonomy classes, see `plan/detail/kategorisierung.md` "Stufe B"). `obj.status` stays the **global** status, so a rule can require the global release before a channel one (`EvaluationRequest` in `protocol.py` carries all fields, `rules_service.evaluate` forwards them).
- `meadow.worker` (`protocol.py`, `rules_service.py`, `log_sender.py`): NATS request/reply service on subjects `rules.evaluate` and `rules.compile` (defaults) that evaluates `EvaluationRequest` payloads and validates scripts via `EvaluationCompileRequest`; rule exceptions are fail-closed (recorded in `failed`). Curated worker logs (rule failures, lifecycle) are buffered (`LogSender`, bounded, drop-oldest) and flushed to `POST /system/logs`; logging config (`log_persist_level`/`log_persist_categories`) is refreshed from `GET /system/settings`. Entry point `python -m meadow.worker`; env `NATS_URL` (default `nats://localhost:4222`), `RULES_EVALUATE_SUBJECT`, `RULES_COMPILE_SUBJECT`, `PIM_CORE_URL` (default `http://localhost:8080`), `LOG_INGEST_API_KEY`, `LOG_FLUSH_INTERVAL_S`, `LOG_CONFIG_REFRESH_INTERVAL_S`.
- `meadow.worker.http` (`http.py`): `loopback_host(url)` rewrites `localhost` → `127.0.0.1` to avoid the Windows IPv6-first resolution stall (~2 s per new connection; the core binds IPv4 only). Every worker HTTP entry point normalises `core_url` through it before issuing requests, and `meadow/frontend/api.py` does the same via `_loopback_host`. Do **not** build core URLs with `localhost`. (Webhook **target** URLs are external and must NOT be rewritten.)
- `meadow.worker.jobs` (`jobs.py`): JetStream job consumer on `jobs.*` (stream `JOBS`, durable pull consumer `job-worker`). `JobRunner` parses `JobMessage`, reports `job_run` status via `PATCH /jobs/runs/{run_id}` (`X-Api-Key` = `LOG_INGEST_API_KEY`), and dispatches to handlers registered by job type; unknown types are marked `failed` + terminated, handler failures are negative-acked for retry; on the final delivery attempt (`num_delivered >= max_deliver`) a failing job is published to the `JOBS_DLQ` stream (`jobs.dlq.<type>`) and terminated. Messages are processed with bounded concurrency (`JOBS_CONCURRENCY`, default 4; `process_messages` + `asyncio.Semaphore`). Env `JOBS_SUBJECT`, `JOBS_STREAM`, `JOBS_CONSUMER_DURABLE`, `JOBS_ACK_WAIT_S`, `JOBS_MAX_DELIVER`, `JOBS_CONCURRENCY`.
- `meadow.worker.business_rules` (`business_rules.py`): the `business_rule` job handler (recompute, Phase 5 step 4; Phase 7 *cascade*). For explicit `object_ids` it loads each object with **`?resolve_inheritance=true`** (plus an optional `parameters.locale`) so computed rules that read inherited values see them; for `applies_to` it loads via `GET /objects`. It evaluates the embedded rule script per object in the sandbox (bulk mode, ~30 s budget), persists declared-computed values via `PATCH /objects/{id}/computed`, and returns a per-object report stored in `job_run.result` (per-object failures are isolated). Sandbox evaluations are serialized by a module-level `asyncio.Lock` (`sys.settrace`/`tracemalloc` are not safe concurrently), while object I/O runs in parallel. A job with `trigger: cascade` is the inherited-computed recompute scheduled by the core after an ancestor save.
- `meadow.worker.imports` (`imports.py`): the `inbound_import` job handler (MEF import, Phase 6). It fetches the stored MEF document (`GET /imports/{document_id}`), applies active `normalization` rules (R3, loaded via `GET /rules`, evaluated in the sandbox with `mode="import"`, serialized on the shared `business_rules.evaluation_lock`), normalizes quantified `{"value":…,"unit":…}` values to the canonical SI unit via `GET /units/convert`, upserts objects through **`POST /objects/batch-upsert`** (`_upsert_batch`; the object loop buffers entries and flushes every `BATCH_UPSERT_SIZE` = 200, so the per-request overhead drops to 1/200 — measured live: 11–25 objects/s with single writes vs **~73 writes/s** batched). Matching stays in the core and mirrors the single path: business key first (`match_by_key`; the batch sends `match_by: "source"` plus the job's key attribute and the core resolves the type's `key_attributes`), then — with `parameters.match_by_id` (`match_by: "id"`) — a MEF `id` that is an existing core record id (a MEF roundtrip), otherwise the source reference (`source` + `source_id`, default source `api`). **Composition is written with the object** (2026-09-17): the document's objects are written **parents-first** (`_parents_first_levels`, breadth-first over the document's `depends_on` edges: a whole level is written and flushed before the next one starts, stable within the document order — a strictly topological order would flush the write batch at every parent/child alternation and drop the import back to single-write speed) and every child carries its parent as `parent` in the batch payload, so the object is created under its real parent in **one** transaction instead of being parked on the universal root and re-parented later. **Channel releases** follow the objects and references (`_import_releases`, `PUT /objects/{id}/releases` per release): a MEF document carries the releases of its objects, so a restore without them would have nothing released; the write runs through the core, which keeps the `workflow_guard` rules in force — a rejected release and a release of an object that was not written are reported, never failing the run. The parent is resolved from the objects written in this run (`id_map`) or, if it belongs to another document, from the system (`GET /objects/by-source`, shared **negative** cache `unresolved` so one missing parent is looked up once for all its children *and* for the reference phase). An object whose parent is neither written in this document nor present in the system is **not created** and reported as `failed` (`composition parent … is neither written in this document nor present in the system`) — before, it was created, hung on `object:object_root` and the run reported `success` (measured 2026-09-17). Two conflicting `depends_on` entries for the same child and a cycle inside the document are reported per object as well (`_composition_parents`, `_parents_first_order`); the report keeps the **document's** order although the writes run parents-first (`object_results` is indexed by MEF position). The per-entry results (`index`/`action`/`error`) are mapped back onto the local objects, and one rejected entry does not fail the batch — the retry pass and the report are unchanged. The per-object `GET /objects/by-key` lookup is gone; `GET /objects/by-source` stays, but only as the cached (`id_map`) resolution of **reference targets** whose object failed earlier (otherwise those edges fail with "cannot resolve" and the retry pass could not repair them — found 2026-09-16: one conflicted category object cost 17 of its `category_member` edges). Then references are created in **batches** (`POST /references/batch`, `BATCH_REFERENCE_SIZE` = 200 rows per call, `references` + `reparents` together — the per-edge round trips were the last bottleneck: measured 11.5 edges/s single-write against a batched object phase at ~141 objects/s, `plan/detail/demodaten-generator.md` §4.3/§4.4). `depends_on` entries travel in the same call as `reparents` (the endpoint applies them as a re-parent, like `PATCH /objects/{id}/parent`, status `reparented`), everything else as `references` (`created`/`existing`); the endpoint answers per entry, so one bad edge does not fail the batch, and a rejected batch reports **every** entry as `failed` so the retry pass re-applies exactly those rows. The report keeps the document's order (`in`/`out`/`type`/`status`, plus `error` for failures), and the MEF `type` name is mapped to the definition key `rel_<name>`. **`depends_on` is applied as a re-parenting** (in the batch as `reparents`, before 2026-09-16 via `PATCH /objects/{id}/parent?emit_events=false`): a new object hangs on the universal root and the composition invariant allows exactly one parent edge, so a second edge would be rejected with `400` — without that handling a MEF document could not express the composition tree (found 2026-09-15 while importing the automotive demo data, `plan/detail/demodaten-generator.md`; the result status is `reparented`). An object with **no** composition edge at all cannot be moved — the core answers `object has no composition parent` — and since a MEF document states the *desired* parent, the worker re-applies exactly those entries as the **initial attach** (a composition edge in `references`, matched via `MISSING_COMPOSITION_PARENT`): without that fallback such an object could never be repaired, and every later import reported the same failure (found 2026-09-17: 65 demo variants stayed parent-less, invisible in the structure tree, while the endpoint kept reporting the error). With `emit_events: false` the writes pass `?emit_events=false` and the handler emits one `import.completed` summary event via `POST /imports/{document_id}/complete`. Writes use the `X-Api-Key` machine-to-machine path. **An existing edge is not a failure:** the core rejects a duplicate reference with `409`, which the handler reports as `existing` (`meadow/worker/bulk.py::_add_relation` treats it as “unchanged”), so a repeated import is idempotent for objects **and** edges (added 2026-09-16). The same `409` also covers a **concurrent write conflict** (“concurrent write conflict, please retry”, the core's mapping of a SurrealDB transaction conflict); that one is *retryable*, so both call sites check the message (`"already exists"`) and report anything else as `failed` — the importer's retry pass then re-applies exactly those objects/references instead of dropping an edge silently. `_raise_for_core_error` raises with the core's `{"error": …}` text (plain `raise_for_status()` would hide it), which is what an operator reads in the run report. **An endpoint missing from the document's `id_map` is resolved once by its source reference** (`GET /objects/by-source?source=&source_id=<mef id>`, cached in the map): a shared object of a chunked import lives in several documents, and if its own entry failed (a lost race) or another chunk is importing it right now, its references would otherwise fail with “cannot resolve” — one conflicted category cost 17 `category_member` edges (found 2026-09-16).
- `meadow.worker.exports` (`exports.py`): the `outbound_export` job handler. **Two paths.** **Das JSON-Dokument ist vollständig (2026-09-17):** both paths resolve the source **completely** (`_page_get`: every list endpoint caps `limit` at 1000, so a type with more objects used to be truncated silently), add the composition ancestors of a partial source (`options.include_ancestors`, default on — an imported object may only be written with its parent), load the edges in bulk (`POST /references/query`, ≤ 500 ids per call, paged; `_mef_references` keeps only edges with both endpoints in the document and counts the rest as `skipped_references`, root edges are dropped silently) and write the channel releases (`?releases=true` → `releases: [{channel, status}]`). `_collect_mef_data` returns `(objects, references, counters)`, `_mef_document` builds the envelope; the source kind `all` is the complete export (every live object except the universal root). Result: `{format, exported, references, skipped_references, added_ancestors, columns, document}`. `_resolve_objects(..., resolve_inheritance=True)` l [truncated]ädt die Objekte mit `?resolve_inheritance=true`, sodass ein strukturierter Export **vererbte** Werte enthalten kann (`options.resolve_inheritance`, Schalter „Auch vererbte Werte exportieren“ in `/export`); ohne die Option werden nur eigene Werte exportiert. - `meadow.worker.webhooks` (`webhooks.py`): the webhook outbound connector (Phase 6). One NATS pull consumer on `events.crud` (stream `EVENTS`, durable `event-webhook`) fans each event out to every configured endpoint (`WebhookFilter`: `event_types`/`object_types`/`attribute_changes`; `WebhookConfig`: `key`, `url`, `method`, `headers`, `timeout_s`, per-connector `coalesce`, per-connector `retry`) with at-least-once semantics: a message is acknowledged only after every matching connector path has settled (`_DeliveryTracker`); delivery failures are negative-acked for NATS redelivery — after the connector's own `retry_policy.max_attempts` (1–10, default 5) and with its `retry_policy.backoff_seconds` (default 5 s) as the nak delay — and dead-lettered to `EVENTS_DLQ` (`events.dlq.webhook`, payload carries the `connector` key) on the final attempt. - `meadow.frontend.api` (`api.py`): the async `CoreClient` wraps the headless core REST API. It **reuses a single long-lived `httpx.AsyncClient`** (`_api_client()` asynccontextmanager; `trust_env=False`) instead of building a new client per call, and `_loopback_host` rewrites `localhost` → `127.0.0.1`. This eliminates the Windows `localhost`-→-IPv6 first-reconnect stall (~2 s) that otherwise added ~2 s per pim-core call — the main cause of the "page starts loading" delay (each page made several sequential calls). Do **not** restore a per-call `httpx.AsyncClient()`. `config.CORE_URL` defaults to `http://127.0.0.1:8080` for the same reason. **Abgelaufene Sitzung:** Der geteilte Client trägt einen **Response-Hook** (`api._watch_session`), sodass **jeder** mit 401 + `invalid or expired token` (`api.SESSION_EXPIRED_MESSAGE`) abgelehnte Aufruf den von `auth.register` gesetzten Handler (`api.set_session_expired_handler`) auslöst. Der Handler (`auth.handle_session_expired`) löscht die Anmeldung (`clear_session`) und leitet auf `/login?redirect_to=<aktuelle Route>&expired=1` um; die Login-Seite zeigt dann `login.session_expired` und bringt den Benutzer nach dem Login zurück. Ein **fehlgeschlagener Login** (401 `invalid credentials`) löst das bewusst nicht aus, die Login-Seite selbst ebenso wenig (die Fehlermeldung bleibt stehen). Der Hook liest den Body explizit (`await response.aread()`) – httpx ruft Response-Hooks aus, bevor der Body konsumiert ist. `list_objects` forwards every grid filter (`type`, `q`, `ids`, `ancestor`, `category`, `definition_id`, `collection`, `uncategorized`, `incomplete`, `where`, …) as query parameters; `where` carries the advanced-search Query DSL as compact JSON.

## Work Guidance

- Code, comments, and docstrings are written in English (root Coding Guidelines).
- Sandbox limits default to the blocking write path (~1.5 s budget, 256 MiB, 64 KB source); bulk jobs may pass looser limits.
- **Sandbox helper set (2026-09-16):** the globals expose RestrictedPython's `safe_builtins`/`limited_builtins`/`utility_builtins` plus pure helpers that its sets omit — `dict`, `sum`, `min`, `max`, `any`, `all`, **`enumerate`**, **`reversed`** — and `getattr` as the **guarded** `RestrictedPython.Guards.safer_getattr` (behaves like the builtin including the default, refuses every `_`-prefixed name). Without `enumerate`/`getattr` the shipped demo rules (`validate_gtin`, `guard_publish_features`) compiled fine but raised `NameError` at runtime, i.e. they silently never ran — `tests/test_demo_data.py::test_every_catalogue_rule_runs_in_the_sandbox` now executes every catalogue rule so this class of gap fails the gate. Compiled scripts are cached per `(source, whitelist, max_source_bytes)` (`sandbox._compiled`, `lru_cache`): `compile_restricted_exec` runs for every rule of every write; errors are not cached, so a broken script keeps failing loudly.
- **A slow core read must never become a 500:** every `@ui.page(...)` passes `response_timeout=PAGE_TIMEOUT` — the constant lives in `layout.py` (env `PIM_PAGE_TIMEOUT`, default 60 s) and each page imports it, because NiceGUI's own default is 3 s per page and there is **no** global switch (`ui.run(response_timeout=…)` does not exist and raises `TypeError`). Fix the read path first; keep this ceiling generous on top.
- **UI-Texte nennen keine Fremdprodukte (2026-09-17, Nutzerentscheidung):** Übersetzungen (`locales/*.json`), Handbuchkapitel (`docs/user/`), Tooltips, Hinweise und Meldungen beschreiben die Funktion in eigenen Worten — **keine** Namen anderer PIM-/Shop-Systeme (der frühere `object_types.subtitle` „STIBO STEP / Akeneo Familien-Modell" ist entfernt). Marktvergleiche gehören ausschließlich in die internen Plan-/Vertragsdokumente (`plan/`, `*/AGENTS.md`), die nie an Kunden ausgeliefert werden.
- **`meadow/ai/` — das Wissen über Regeln, aus den Laufzeitquellen (Stufe 0, 2026-09-19):** kein Modell, kein Provider, keine I/O — nur die Fakten, die ein Regel-Autor (Mensch oder später ein Modell) braucht. `policy.py` liest die **laufende Sandbox** (`build_globals`): verfügbare Built-ins, Import-Whitelist, Grenzen, injizierte Globals — und leitet daraus `forbidden_helpers()` ab (Kandidatenliste **minus** dem, was wirklich existiert), damit die Liste nicht gegen die Laufzeit driftet. `check_script(source)` prüft zweistufig: AST-Vorprüfung (genau eine Funktion `run` mit `(obj, ctx, result)`, keine Namen aus der Verbotsliste) **und** `compile_rule` (Politik). Die Trennung ist gemessen: `hasattr` besteht `compile_restricted_exec` und scheitert erst mit `NameError`, verbotene Imports und private Attribute lehnt der Compiler schon ab. `context.py` erzeugt daraus Textblöcke (`contract_block()` mit Signaturen **per `inspect`** aus `meadow.rules.contract`, `policy_block()`) und die **Projektion** `attribute_facts(vocabulary, object_type)` — nur **eigene** Attribute (ohne `reference_data`); das ist die Voraussetzung dafür, dass ein Kontext überhaupt passt (gemessen: 17 463 Definitionen, für `product` 17 443 zutreffend, Namensliste 174 654 Zeichen — gegenüber 54 eigenen, 1 107 Zeichen). `examples.py` liefert die kuratierten Few-Shot-Regeln; sie liegen **im Paket**, weil das Frontend-Image nur `meadow/` und `docs/user/` kopiert (`docker/Dockerfile.frontend`), also keine Datei unter `scripts/`. - **KI-Assistenz, Stufe 1 (2026-09-19):** die Erzeugung läuft im **Worker** (`meadow/worker/ai_service.py` über die Subjects `ai.generate`/`ai.test`), weil dort `httpx`, die Sandbox und der bestehende Außen-I/O sitzen.
