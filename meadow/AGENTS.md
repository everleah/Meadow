# meadow — Python Source Code

## Purpose

Owns the Python package `meadow`: the shared business-rules engine (`meadow.rules`), and later the worker and frontend services. Python is the home of flexible business logic and the UI (see root AGENTS.md).

## Ownership

- Owns all files under `meadow/`.
- `meadow/rules/` — RestrictedPython sandbox and the script contract `run(obj, ctx, result)`.
- `meadow/tabular.py` — shared CSV/XLSX ↔ MEF adapter (pure parsing/mapping helpers).
- `meadow/mef.py` — pure MEF JSON helpers (detect/parse/summarize, preview rows) for the import page.
- `meadow/worker/` — async NATS request/reply worker serving `rules.evaluate` (`python -m meadow.worker`).
- `meadow/frontend/` — the NiceGUI web application (`python -m meadow.frontend`).
- `meadow/frontend/static/` — static client assets (logos, images, icons); owned by `meadow/frontend/static/AGENTS.md`.

## Local Contracts

- Implementation stays consistent with `plan/detail/business-rules.md` and the root AGENTS.md (package manager `uv`, `.venv/`, `pyproject.toml`).
- The rules engine is a shared library; its consumers are the Rust core (synchronous evaluation endpoint, Phase 4) and the Python worker/frontend.
- `meadow.rules` public API: `execute_rule`, `compile_rule`, `Context`, `Result`, `DEFAULT_WHITELIST`, and the `RuleError` hierarchy (`RuleCompileError`, `RuleTimeoutError`, `RuleMemoryError`).
- Rule scripts use `def run(obj, ctx, result)`; injected globals are `obj` (read-only view), `ctx`, `result`, `log`, plus whitelisted modules (default: `json`, `datetime`, `math`, `re`, `statistics`, `decimal`, `typing`, `uuid`, `collections`).
- `meadow.worker` (`protocol.py`, `rules_service.py`, `log_sender.py`): NATS request/reply service on subjects `rules.evaluate` and `rules.compile` (defaults) that evaluates `EvaluationRequest` payloads and validates scripts via `EvaluationCompileRequest`; rule exceptions are fail-closed (recorded in `failed`). Curated worker logs (rule failures, lifecycle) are buffered (`LogSender`, bounded, drop-oldest) and flushed to `POST /system/logs`; logging config (`log_persist_level`/`log_persist_categories`) is refreshed from `GET /system/settings`. Entry point `python -m meadow.worker`; env `NATS_URL` (default `nats://localhost:4222`), `RULES_EVALUATE_SUBJECT`, `RULES_COMPILE_SUBJECT`, `PIM_CORE_URL` (default `http://localhost:8080`), `LOG_INGEST_API_KEY`, `LOG_FLUSH_INTERVAL_S`, `LOG_CONFIG_REFRESH_INTERVAL_S`.
- `meadow.worker.http` (`http.py`): `loopback_host(url)` rewrites `localhost` → `127.0.0.1` to avoid the Windows IPv6-first resolution stall (~2 s per new connection; the core binds IPv4 only). Every worker HTTP entry point normalises `core_url` through it before issuing requests, and `meadow/frontend/api.py` does the same via `_loopback_host`. Do **not** build core URLs with `localhost`. (Webhook **target** URLs are external and must NOT be rewritten.)
- `meadow.worker.jobs` (`jobs.py`): JetStream job consumer on `jobs.*` (stream `JOBS`, durable pull consumer `job-worker`). `JobRunner` parses `JobMessage`, reports `job_run` status via `PATCH /jobs/runs/{run_id}` (`X-Api-Key` = `LOG_INGEST_API_KEY`), and dispatches to handlers registered by job type; unknown types are marked `failed` + terminated, handler failures are negative-acked for retry; on the final delivery attempt (`num_delivered >= max_deliver`) a failing job is published to the `JOBS_DLQ` stream (`jobs.dlq.<type>`) and terminated. Messages are processed with bounded concurrency (`JOBS_CONCURRENCY`, default 4; `process_messages` + `asyncio.Semaphore`). Env `JOBS_SUBJECT`, `JOBS_STREAM`, `JOBS_CONSUMER_DURABLE`, `JOBS_ACK_WAIT_S`, `JOBS_MAX_DELIVER`, `JOBS_CONCURRENCY`.
- `meadow.worker.business_rules` (`business_rules.py`): the `business_rule` job handler (recompute, Phase 5 step 4; Phase 7 *cascade*). For explicit `object_ids` it loads each object with **`?resolve_inheritance=true`** (plus an optional `parameters.locale`) so computed rules that read inherited values see them; for `applies_to` it loads via `GET /objects`. It evaluates the embedded rule script per object in the sandbox (bulk mode, ~30 s budget), persists declared-computed values via `PATCH /objects/{id}/computed`, and returns a per-object report stored in `job_run.result` (per-object failures are isolated). Sandbox evaluations are serialized by a module-level `asyncio.Lock` (`sys.settrace`/`tracemalloc` are not safe concurrently), while object I/O runs in parallel. A job with `trigger: cascade` is the inherited-computed recompute scheduled by the core after an ancestor save.
- `meadow.worker.imports` (`imports.py`): the `inbound_import` job handler (MEF import, Phase 6). It fetches the stored MEF document (`GET /imports/{document_id}`), applies active `normalization` rules (R3, loaded via `GET /rules`, evaluated in the sandbox with `mode="import"`, serialized on the shared `business_rules.evaluation_lock`), normalizes quantified `{"value":…,"unit":…}` values to the canonical SI unit via `GET /units/convert`, upserts objects by business key (`match_by_key`, via `GET /objects/by-key`), then — with `parameters.match_by_id` — by an existing core record id (`GET /objects/{id}`, for MEF documents whose `id` is a Meadow record id, i.e. a MEF roundtrip) — or by source reference (`GET /objects/by-source`, the MEF object `id` + document `source`; `source_id`/`source` stored via `POST /objects`), then `POST /objects`/`PATCH /objects/{id}`, creates references (mapping the MEF `type` name to the definition key `rel_<name>`), and returns a per-object/per-reference report stored in `job_run.result` (failures are isolated). With `emit_events: false` the writes pass `?emit_events=false` and the handler emits one `import.completed` summary event via `POST /imports/{document_id}/complete`. Writes use the `X-Api-Key` machine-to-machine path.
- `meadow.worker.exports` (`exports.py`): the `outbound_export` job handler. **Two paths.** (1) `json_export` connector (Phase 6): filters objects by `parameters.filter` (`type`/`status`; `status` filtered client-side), fetches them via `GET /objects`, re-emits quantified values (canonical-SI numbers) as `{"value":…,"unit":…}` in the attribute's display unit (attribute definitions via `GET /attribute-definitions`; conversion via `GET /units/convert`), builds a MEF document (`format_version`, `source`, `created_at`, `objects`), and stores it in `job_run.result` (`{connector, exported, document}`). (2) **Structured export (Phase 9, UI-guided):** when `parameters.source` is set (`collection|type|category|saved_search|selection`), it resolves the object set via `_resolve_objects` (collection → `GET /collections/{id}/members`; saved_search → `POST /saved-searches/{id}/execute`; selection → `object_ids`; then `GET /objects?ids=...`), loads multilingual/language-map metadata (`_load_multilingual`/`_load_languages`), builds columns/rows (`_build_columns`/`_build_rows`, expanding multilingual attributes into `<attr>_<locale>` columns with fallback via `_pick`), and stores `{format, exported, columns, csv|document|xlsx_base64}` in `job_run.result` (no binary blob; the file is serialised by `GET /exports/{run_id}/file`). CSV via `csv.writer` (`_serialize_csv`), XLSX via openpyxl (`_serialize_xlsx`). When `options.email_to` is set, `_maybe_email` sends the finished file as an attachment (best-effort; the outcome is recorded under `result.email`). `_finalize` runs **archival + e-mail** after the result is built: when S3 is configured (`meadow.worker.storage`) the file is uploaded and, above `EXPORT_INLINE_MAX_BYTES` (default 1 MB), the inline `csv`/`xlsx_base64`/`document` are dropped — `result.archive` then holds `{bucket, key, size, url, expires_in}` (a presigned download URL). Registered in `meadow/worker/__main__.py`.
- `meadow.worker.mail` (`mail.py`): minimal env-configured SMTP sender for the worker. `SmtpConfig.from_env()` reads `SMTP_HOST` (unset = disabled), `SMTP_PORT` (default 1025), `SMTP_FROM` (default `meadow@localhost`), optional `SMTP_USERNAME`/`SMTP_PASSWORD` and `SMTP_STARTTLS`; `send_with_attachment(...)` sends one plain-text e-mail with a single attachment via `aiosmtplib`. For local development the `mailhog` service in `docker-compose.dev.yml` catches all mail (SMTP 1025, web UI/API 8025).
- `meadow.worker.storage` (`storage.py`): S3/MinIO archival for export results (path-style SigV4 via `boto3`). `S3Config.from_env()` reads `S3_ENDPOINT_URL`/`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`/`S3_BUCKET`/`S3_REGION`/`S3_PRESIGN_EXPIRY` (unset endpoint/bucket = disabled); `archive_export(config, key, content, content_type, download_name)` creates the bucket on demand, uploads the bytes and returns `{bucket, key, size, url, expires_in}` with a presigned GET URL. Dev uses the `minio` service in `docker-compose.dev.yml` (API 9000, console 9001).
- `meadow.worker.connectors` (`connectors.py`): loads enabled connectors from the core (`GET /connectors?type=…&enabled=true` with `X-Api-Key`) into typed config models. `fetch_webhook_configs` raises on transport failure; `load_webhook_configs` combines it with the `env_bootstrap_config()` fallback (`WEBHOOK_URL`, …) so the `connector` table is the durable source of truth and environment variables only seed the initial value.
- `meadow.worker.webhooks` (`webhooks.py`): the webhook outbound connector (Phase 6). One NATS pull consumer on `events.crud` (stream `EVENTS`, durable `event-webhook`) fans each event out to every configured endpoint (`WebhookFilter`: `event_types`/`object_types`/`attribute_changes`; `WebhookConfig`: `key`, `url`, `method`, `headers`, `timeout_s`, per-connector `coalesce`) with at-least-once semantics: a message is acknowledged only after every matching connector path has settled (`_DeliveryTracker`); delivery failures are negative-acked for NATS redelivery and dead-lettered to `EVENTS_DLQ` (`events.dlq.webhook`, payload carries the `connector` key) on the final attempt. When `coalesce.enabled` is set, events are buffered per connector/`object_id`+`event_type` and a flush loop delivers only the last event per window (with `coalesced`/`bundled_count` flags), acknowledging the buffered messages on flush. `serve_webhooks_dynamic` supervises the consumer and **live-reloads** connector config every `WEBHOOK_RELOAD_INTERVAL_S` (default 30) — on change the consumer task is restarted with the new config (shared durable consumer keeps at-least-once across restarts), so no worker restart is required; a load failure keeps the current config. Env fallback: `WEBHOOK_URL`, `WEBHOOK_METHOD`, `WEBHOOK_HEADERS`, `WEBHOOK_FILTER_EVENT_TYPES`/`_OBJECT_TYPES`/`_ATTRIBUTES`, `WEBHOOK_COALESCE_ENABLED`, `WEBHOOK_COALESCE_WINDOW_S`, `WEBHOOK_ACK_WAIT_S`, `WEBHOOK_MAX_DELIVER`, `WEBHOOK_NAK_DELAY_S`.
- `meadow.worker.collections` (`collections.py`): the `collection_refresh` job handler (Phase 9). It reads `message.parameters.collection_id` and calls `POST /collections/{id}/refresh` (X-Api-Key) on the core, returning `{collection_id, count}` stored in `job_run.result`. Registered in `meadow/worker/__main__.py`.
- `meadow.worker.config_import` (`config_import.py`): the `config_import` job handler (MCF, Phase 9). It reads `message.parameters` `{document_id, mode}` (`dry_run`|`merge`|`replace`), fetches the stored MCF document (`GET /imports/{document_id}`), re-applies it via `POST /config/import?mode=...` (X-Api-Key), and returns `{mode, report}` stored in `job_run.result`. Registered in `meadow/worker/__main__.py`.
- `meadow.worker.bulk` (`bulk.py`): the `bulk_operation` job handler (Bulk-Wizard, Phase 7). It reads `message.parameters` `{op, object_ids, parameters}`, applies the operation per object (`set_attribute`/`clear_attribute` via `PATCH /objects/{id}`, `change_status`, `add_category`/`remove_category` via `POST`/`DELETE /references`, `change_parent`, `delete`), isolates per-object failures, and returns `{op, processed, succeeded, failed, results[]}` stored in `job_run.result`.
- `meadow.tabular` (`tabular.py`): the pure CSV/XLSX → MEF adapter shared by the frontend import page (and any future worker-side adapter). `parse_csv` (delimiter sniffing `,;\t|`, decoding `utf-8-sig`/`utf-8`/`cp1252`/`latin-1`), `parse_xlsx`/`sheet_names` (openpyxl, read-only/data-only), `parse_table(name, content, …)` dispatches by extension (`.xlsx`/`.xlsm` → XLSX, else CSV), `build_mef(table, mapping, default_type=…, source=…)` builds a MEF document from `TableData(columns, rows)`. Mapping target syntax: `""` = ignore, `id`/`type`/`status` = base fields, `<attribute>` = plain value, `<attribute>|<locale>` (`LOCALE_SEPARATOR`) = multilingual `{locale: value}`. Empty `type`/`status` cells fall back to the default type / `draft`. The module is import-light (openpyxl is imported lazily inside the XLSX functions).
- `meadow.frontend.attribute_definitions` (`attribute_definitions.py`): the `/attribute-definitions` admin page (admin/superadmin only) listing attribute definitions in an AG-Grid and providing a create/edit dialog over `POST`/`PATCH /attribute-definitions` (fields `type`, `label` (en/de), `group_ids` (list, many-to-many), `inheritable`, `is_key`, `multilingual`, `applicable_types`/`required_types`, `unit_id`/`display_unit_id`, `enum_set_id`, `description`, `computed` fields). **Enum attributes reference a reusable enum set (Phase 9):** for `enum` attributes the dialog shows an **`Enum set` select** (`enum_set_select`, options from `client.list_enum_sets`, keyed by the full `enum_set:<key>` id) plus a **"Manage enum sets"** button (→ `/enum-sets`); on save it sends `enum_set_id` instead of `constraints.enum_values`. The option list/remap editor moved to the `/enum-sets` admin page. `views.py` registers it via `_IMPLEMENTED_ROUTES`. Double-click on a grid row opens the edit dialog (resolves the full definition by id from `definitions`). A **delete** action (`DELETE /attribute-definitions/{id}`, `?force=true` for in-use definitions) shows a confirmation dialog and surfaces the 409 conflict message when the attribute is in use. An inline **Attribute groups** section (`group_grid`) allows create/edit/delete of groups (`POST`/`PATCH`/`DELETE /attribute-groups`, fields `name`, `label`, `position`, `applicable_types`), and the group column in the grid renders all groups of an attribute (the dialog's group select is `multiple=True`). The group grid also offers an **Edit-group** button and a **column picker** (dialog) that toggles column visibility and persists the per-user visibility in `app.storage.user["attr_def_group_columns"]` (mirrors the product grid's saved views). Editing resolves the **full** group record by id (`_group_for`) — the rendered rows carry resolved display strings (label, comma-joined `applicable`), not the raw `label` dict / `applicable_types` list the editor needs. A **filter bar** (free-text name, group select, type select) above the definition grid narrows the rows client-side (`filters` + `_matches`). The `Attribute groups` expansion uses a green header (`header-class=bg-green-2 text-green-9`), matching the product-form section headers.
- `meadow.frontend.enum_sets` (`enum_sets.py`): the `/enum-sets` admin page (admin/superadmin only, nav „Enum Sets“) for **reusable enum sets (Reference Data)**. It lists sets (`client.list_enum_sets`) in an AG-Grid (Name, Label, Options count, Position, Updated) with a name filter, and a create/edit dialog over `POST`/`PATCH /enum-sets`: `name` (read-only on edit), `label` en/de, `position`, and a **"Manage options"** action. The options editor dialog (`render_options`, refreshable) manages the set's options per row (`code` + EN/DE labels + `active` + remove); **Add option** appends a row, saving reconciles via `POST`/`PATCH /enum-options` and `PATCH /enum-sets/{id}` with `options` + `option_remap` (a removed used option opens a **re-map dialog**). `DELETE /enum-sets/{id}` is blocked (409) while an attribute references it. `api.CoreClient` gained `list_enum_sets`/`create_enum_set`/`update_enum_set`/`delete_enum_set`/`list_enum_options`/`create_enum_option`/`update_enum_option`/`delete_enum_option`.
- `meadow.frontend.enums` (`enums.py`): pure helpers to resolve a definition's enum set (`set_for_definition`), its `[{code,label}]` for a locale (`enum_options`), a `{code:label}` map (`enum_code_label_map`) and a single label (`enum_label_for`). Falls back to `constraints.enum_values` when a definition references no set. Used by the product form (`form.py`) and the object grid (`grid.py`).
- `meadow.frontend.multilang` (`multilang.py`): reusable **multilingual value editor** (`multilingual_value_editor`, `base_lang`, `active_data_languages`). Renders a current-UI-language input + language-icon button (dialog for all active data languages) and writes a `{lang: value}` map into `store[key]`; `in_row=False` renders inline for compact rows. Replaces the old hard-coded `Label (DE)`/`Label (EN)` input pairs in the admin dialogs (attribute definitions/groups, units, object types, relation types, enum sets incl. option labels).
- `meadow.frontend.units` (`units.py`): the `/units` admin page (admin/superadmin only) for **unit catalog management** (nav „Units“). It lists the catalog (`GET /units`) in an AG-Grid (Symbol, Label, Dimension, SI base, Factor, Offset, System) with a **filter bar** by dimension (client-side via `filters` + `_matches`) and a **System badge** column rendered via `html_columns` (default = neutral, custom = warning). A **"New unit"** button and row **double-click** open a create/edit dialog over `POST`/`PATCH /units`: fields `symbol`, `Base unit (SI)` select (from the catalog, sends the **bare** record key e.g. `unit_m`), `Label (DE/EN)` (hybrid editor: current-UI-language input + language icon for all data languages), `Factor`, `Offset`; on **edit** the symbol and base are read-only and a **Delete** button (`DELETE /units/{id}`, confirmation dialog) is shown for custom units. `api.CoreClient` gained `list_units`/`create_unit`/`update_unit`/`delete_unit`/`convert_units`. The `attribute_definitions` dialog's `unit_input`/`display_input` are **`ui.select`** dropdowns populated from the unit catalog (`unit_options`, keyed by bare key, resolved via `_unit_key`/`unit_key_by_symbol`/`_resolve_unit_key`).
- `meadow.frontend.object_types` (`object_types.py`): the `/object-types` admin page (admin/superadmin only, nav „Object Types“) for the **object-type registry** (flat, STIBO STEP / Akeneo family model). It lists types (AG-Grid: Name/Label/Key attributes/Label attribute/**Type**/Updated) with a name filter and a **Type badge** column rendered via `html_columns` (system = neutral, custom = warning), a create/edit dialog (`name` read-only on edit, `label` en/de, `description`, **`key_attributes` multi-select** + **`label_attribute` select** populated from `text` + non-multilingual attribute definitions), **Save/Reload**, and **Delete** (`client.delete_object_type`, confirmation, **409 when still used**; `system` types are locked client-side with a „System types cannot be deleted.“ notification and rejected server-side with 400). `api.CoreClient` gained `list_object_types`/`create_object_type`/`update_object_type`/`delete_object_type`. The `/attribute-definitions` page now populates its `applicable_types`/`required_types` dropdowns from the registry (`GET /object-types`) instead of deriving types from existing objects.
- `meadow.frontend.saved_searches` (`saved_searches.py`): the `/saved-searches` admin page (admin/superadmin only, nav „Searches & Collections“) with two tabs. **Saved Searches** (AG-Grid: Name/Refresh interval/Updated) with a name filter bar, create/edit dialog (`name`, `refresh_interval`, **query as JSON `ui.codemirror`** — the Query DSL), a **Run** action (`client.execute_saved_search` → `POST /saved-searches/{id}/execute`) showing `{count, ids}`, and **Delete** (`client.delete_saved_search`). **Collections** (AG-Grid: Name/Source search/Members/Refresh interval/Last refreshed) with a name filter, create/edit dialog (`name`, `saved_search` select, `refresh_interval` cron), **Refresh** (`client.refresh_collection`, confirmation), **Members** dialog (`client.list_collection_members`, table with Rank/Object/Type/Status), **Add members** dialog (`client.add_collection_members` → `POST /collections/{id}/members`, paste object IDs one-per-line/comma-separated, shows `added`/`skipped`), **Export** (navigates to `/export?collection=<id>` preselecting the collection source), and **Delete** (`client.delete_collection`). `api.CoreClient` gained `list_saved_searches`/`create_saved_search`/`update_saved_search`/`delete_saved_search`/`execute_saved_search`/`list_collections`/`create_collection`/`update_collection`/`delete_collection`/`refresh_collection`/`list_collection_members`/`add_collection_members`.
- `meadow.frontend.relation_definitions` (`relation_definitions.py`): the `/relation-definitions` admin page (admin/superadmin only, nav „Relation Types“) for the **relation-type registry** (composition `depends_on` + aggregations `category_member`/`collection_member`/`related`, plus custom aggregations). It lists types (AG-Grid: Name/Label/**Kind**/Source types/Target types/**Attributes**/**Type**/Updated) with a name filter and **Kind** + **Type** badge columns (`html_columns`; composition=orange/aggregation=blue, system=neutral/custom=warning), a create/edit dialog (`name` read-only on edit, `label` en/de, **Kind** select (disabled — custom types are always aggregation), **Allowed source types**/**Allowed target types** multi-selects (from the object-type registry), **Edge attributes** multi-select (from attribute definitions)), **Save/Reload**, and **Delete** (`client.delete_relation_definition`, confirmation, **400 for system types** and **409 when still used**; `system` types are locked client-side). `api.CoreClient` gained `create_relation_definition`/`update_relation_definition`/`delete_relation_definition`/`update_reference` (and `create_reference` accepts optional `attributes`).
- `meadow.frontend.jobs` (`jobs.py`): the `/jobs` admin page (admin/superadmin only) with two tabs. **Definitions** lists job definitions (`GET /jobs`) in an AG-Grid (name, type, schedule, enabled, updated) with a **job-type filter** (`Job type` select over `JOB_TYPES`, client-side), a create/edit dialog (`POST`/`PATCH /jobs`, fields `name`, `type`, cron `schedule`, `parameters` as JSON, `enabled`), a **Run** action (`POST /jobs/{id}/run`) behind a confirmation dialog, and a **Delete** action (`DELETE /jobs/{id}`) behind a confirmation dialog that also warns the definition's runs are removed. `JOB_TYPES` **mirrors the core's `VALID_JOB_TYPES`** (`outbound_export`, `inbound_import`, `business_rule`, `bulk_operation`, `collection_refresh`, `config_import`) — keep both lists in sync when a job type is added. **Runs** shows the `job_run` history (`GET /jobs/runs`, newest first) with a status badge (`html_columns` for the `status` field), trigger, start/finish, duration, error and a **DLQ marker** (❗ when the error contains "dead lettered"); a status filter plus a **"Dead letters only"** switch, polling every ~5 s, a detail dialog (status, error, pretty `result`) opened on row double-click, and a **Delete** action (`DELETE /jobs/runs/{run_id}`) behind a confirmation dialog. `api.CoreClient` gained `list_job_definitions`/`create_job_definition`/`update_job_definition`/`run_job`/`list_definition_runs`/`delete_job_definition`/`delete_job_run`.
- `meadow.frontend.users` (`users.py`): the combined `/users` admin page (admin/superadmin only, nav „Users & Groups“) that hosts **users** and **groups** on one screen (mirroring `/attribute-definitions`, which hosts definitions + attribute groups). **Users**: AG-Grid (`GET /users`, `password_hash` omitted; username, email, roles, status, **password** (`_password_badge`: `new` = the user still has to set their own password, `ok` = vouched/changed; an absent `must_change_password` counts as `new`), locale, updated) with a **filter bar** (free-text name, role select, status select — analogous to the attribute-definitions filter, client-side via `user_filters` + `_user_matches`) and a create/edit/delete dialog (`POST`/`PATCH`/`DELETE /users`; `username` read-only on edit, `password` only set on create/change, `roles` multi-select, `status`, `locale`, plus the **`must_change_password` switch** — "Require a new password", default on; off for passwords handed over as final, e.g. integration accounts). `_fill_user_form` works on `user or {}` so the create path never touches `None`, and `_user_for(data)` resolves the **full** record by id (grid rows carry display strings — e.g. `roles` joined with commas, which would be sent back as the role list and trip the core's last-superadmin guard). The roles select uses `ui.select(..., multiple=True)` (a `multiple` **prop** alone leaves NiceGUI unaware of list values, so `set_value([...])` is silently ignored and editing would drop the roles). For `superadmin` a **"Login as"** action (`POST /auth/impersonate/{user_id}`) switches the session to the target user's roles: it stores the impersonation token + the `impersonator` claim in `app.storage.user` and navigates to `/`. `auth.is_superadmin()` gates the button. **Groups**: an expandable section (green `ui.expansion` header) listing groups (`GET /groups`) in an AG-Grid (name, grant/deny permissions, scope, branding) with a create/edit/delete dialog (`POST`/`PATCH`/`DELETE /groups`; grant/deny as comma/`;` lists, `scope`/`branding` as JSON textareas). `groups.py` now only redirects `/groups` → `/users` (kept so old bookmarks work); the standalone `/groups` page was removed and the nav entry combined.
- **Impersonation (frontend):** `build_shell` (`layout.py`) renders a warning banner („Signed in as `<user>` (via `<actor>`)") with a **"Back to own session"** button (`logout`) when `app.storage.user["impersonator"]` is set; a normal login clears `impersonator`. The role guard (`auth.is_admin()`) hides admin nav items for an impersonated (non-admin) session.
- `meadow.frontend.password` (`password.py`): self-service password change. `open_change_password_dialog()` renders the dialog (current/new/repeated password, `MIN_PASSWORD_LENGTH` = 8 mirroring the core, client-side checks for length and equality) and calls `CoreClient.change_password` (`POST /auth/password`); on success it stores the **returned fresh token** in `app.storage.user` (the core bumps `token_version`) and clears the hint (`must_change_password=False`). `refresh_banner()` is rendered by `build_shell` and asks the user to set their own password while `needs_password_change()` is true — i.e. `GET /auth/me` returned `must_change_password` **true** (absent counts as true: the seeded `admin`/`admin` or a password an admin handed over with "require a new password" checked). An admin who vouches for the password (unchecked box in `/users`, `must_change_password: false`) or the user's own change turns it off. - `meadow.frontend` (`frontend/`): the NiceGUI web app (`python -m meadow.frontend`). Entry `__main__.main` applies the Meadow branding (`theme.apply_branding` → `app.colors()`), registers the auth middleware (`auth.AuthMiddleware`, redirects unauthenticated users to `/login`) and the views, then `ui.run(host, port, storage_secret, reload=False)`. `main` calls `_patch_engineio_disconnect_guard()` first, which patches `engineio.AsyncServer.handle_request` to swallow the benign `KeyError: 'REQUEST_METHOD'` raised when a client disconnects mid-poll (engineio upstream gap — its async `translate_request` returns an empty `environ` on `http.disconnect`; see the `__main__.py` docstring). A URL filter (`?incomplete`, `?type`, `?ancestor`, `?category`, `?collection`, `?uncategorized`) loads the targeted objects; a tree selection updates the URL (`history.replaceState`) so a save/reload keeps the view. The grid offers three left-panel views via icon buttons (`account_tree` = structure, `category` = categories, `collections_bookmark` = **Collections**): the **Collections** view is flat — it loads `client.list_collections` and renders each collection as a tree node (label + `collection` type + member count); selecting one calls `client.list_objects(token, collection=<id>)` and filters the grid via `GET /objects?collection=<id>` (`collection_member` aggregation). The action button in the filter row is view-dependent: **`unfold_less` (collapse-all)** only in the structure/category views, replaced by a **`refresh` (reload)** button in the Collections view (`reload_collection` → `POST /collections/{id}/refresh` to re-materialize members, then `client.list_collections` to refresh the member counts and `client.list_objects(collection=...)` to re-fetch the grid). While a collection is selected the tree/selection is **left untouched** on reload — re-sending the node list (e.g. via `set_nodes`/`update`) corrupts the LazyTree selection so the node toggles off on the next click; the tree is only re-rendered (to update counts) when no collection is selected. Leaving the Collections view resets the active collection, clears the `?collection=` URL param, and returns to the structure view. The **bulk-wizard pickers** (category options for `add_category`/`remove_category`, parent options for `change_parent`) are loaded **lazily on first use** (`load_category_options`/`load_parent_options`), not on every `/products` render. The **column picker** is a **`ui.dialog`** (not a `ui.menu`): Quasar's `QMenu` auto-open does not fire in Firefox/Zen (both the sibling and the nested button/menu forms fail there), whereas a `ui.dialog` opens reliably in all browsers — the same pattern as the working "views" dialog. The toolbar is right-aligned (`Save` stays a text button, while `Discard`/`Views`/`Columns` are icon-only with tooltips) with the structure-panel toggle (`view_sidebar`) and the staged-change counter on the far left. The structure panel renders a **`LazyTree`** (`meadow/frontend/lazy_tree.py`, a `ui.tree` subclass) that **lazy-loads** children on expand: nodes with `hasChildren` are marked `lazy: true` (no `children` key) and Quasar `@lazy-load` is wired through a client-side `js_handler` (captures the `done(children)` callback in `window.__meadowLazy`, emits the node key) so the server fetches children (`CoreClient.list_object_children`, paginated) and feeds them back via `run_javascript`; the tree is height-constrained to its card (`min-height: 0`) and scrolls internally (`overflow-y: auto`) so the panel does not overflow (`virtual-scroll` is set but does not take effect in this NiceGUI/Quasar version). `LazyTree.update()` is a **no-op**: NiceGUI re-sends the whole `nodes` prop on *any* prop change (e.g. `selected`), which would discard the client-side lazy children and collapse the tree; node changes (the tree's search filter) are applied explicitly through `LazyTree.set_nodes()` (which re-sends the (filtered) node list via `super().update()`). Top-level nodes load from the Universal-Root via `list_object_children`, and **selecting a node filters the grid server-side** through `CoreClient.list_objects(ancestor=...)` (the client no longer holds the full tree). The grid also shows a **completeness column** (`_completeness`, coloured `completeness_badge`: grey 0 %, orange 1–99 %, green 100 %), fed by the core's `completeness` value for the working locale (`list_objects(..., locale=...)`, which passes `?locale=`); the `_status` and `_completeness` columns are registered as `html_columns` so their badge HTML renders instead of being escaped. The left panel has a **two-line header** — line 1 a **`ui.button_group`** of two icon buttons (`account_tree` = Structure, `category` = Categories; active `color=primary`, tooltips) that switch the tree view, line 2 the filter field + collapse buttons. `set_view(view)` styles the active button, toggles the tree-selector visibility, and calls `render_tree(view)`, which clears a `host` column and rebuilds a `LazyTree` for the structure (all types, `?ancestor=` filter) or for the categories (`type == "category"` children only, loaded with `count_members=True` and shown with a `memberCount` counter in the node label; selection filters the grid via `list_objects(..., category=...)` → `?category=` aggregation). The grid also has a **reference column** (`_refs`, 🔗) and a **reference-picker modal** (`ref_dialog`): clicking a row's 🔗 cell routes `grid.on('cellClicked', handle_ref_cell_clicked, ['data','colId'])` to `open_references(object_id)`; the modal lists the object's references **grouped & sorted by relation type** (composition `rel_depends_on` first, then aggregations by label; resolving the type label via `list_relation_definitions`), each chip carrying a remove button calling `delete_reference` (hidden for the composition `rel_depends_on`), an **empty-state message** (`grid.ref_empty`) when there are no references, a **relation-type dropdown** (`relation_options` from `list_relation_definitions` filtered to `kind == 'aggregation'`, keyed by the definition's **short record key** e.g. `rel_category_member` because `create_reference` expects that), and a **search field** (`search_references` → `picker_search`) whose hits are added via `add_reference` (`create_reference`). A **Relations** section (`build_relations_section`) renders the object's **graph-edge relations** (`CoreClient.list_object_references`), **grouped by relation type** (`CoreClient.list_relation_definitions`; composition `depends_on` first, then aggregations by label) as **full-width coloured cards with a darker header** (orange = composition, blue = aggregation; header `bg-orange-2`/`bg-blue-2`, body `bg-orange-1`/`bg-blue-1`) carrying **Composition/Aggregation badges**, per-type counts, an **add picker** (`CoreClient.picker_search`, filtered by `target_types` → `POST /references`), **remove** per aggregation (`DELETE /references/{id}`), a **re-parent** action for `depends_on` (`PATCH /objects/{id}/parent` via `CoreClient.reparent_object`), and **open target** navigation. An **"Only missing required fields" switch** (`form_show_missing` in `app.storage.user`) filters the section rows to the missing required attributes (`missing_required`) via a `ui.refreshable`. A **completeness widget** and a **status selector** are shown; saving via `PATCH /objects/{id}` **surfaces the core's `error` message** (`CoreClient.update_object` raises `CoreError`) instead of a generic failure. The **grid export** (toolbar download button) opens a dialog with scope (**selected rows** / **all filter matches**) and format (CSV/XLSX/JSON); it posts a `selection` source to `POST /exports` (`client.create_export`), polls the job run (`_wait_export`) and downloads via `GET /exports/{run_id}/file` (`client.get_export_file`), reusing the currently visible grid columns as the field set (`_export_fields`, maps `_id`/`_type`/`_status`/`_name`/`attr_*` to `id`/`type`/`status`/`name`/`<attr>`). The products page uses `response_timeout=15`. Config env: `PIM_CORE_URL` (default `http://localhost:8080`), `PIM_FRONTEND_HOST`/`PIM_FRONTEND_PORT` (default `8081`), `UI_STORAGE_SECRET`.

- `meadow.frontend.api` (`api.py`): the async `CoreClient` wraps the headless core REST API. It **reuses a single long-lived `httpx.AsyncClient`** (`_api_client()` asynccontextmanager; `trust_env=False`) instead of building a new client per call, and `_loopback_host` rewrites `localhost` → `127.0.0.1`. This eliminates the Windows `localhost`-→-IPv6 first-reconnect stall (~2 s) that otherwise added ~2 s per pim-core call — the main cause of the "page starts loading" delay (each page made several sequential calls). Do **not** restore a per-call `httpx.AsyncClient()`. `config.CORE_URL` defaults to `http://127.0.0.1:8080` for the same reason.
- Frontend static assets are served from `meadow/frontend/static/` under `/static` (`app.add_static_files`); `/static` is exempt from the `AuthMiddleware` so unauthenticated pages (login) can load branding assets. See `meadow/frontend/static/AGENTS.md`.
